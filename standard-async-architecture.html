一、同步 vs 異步 核心差異

同步架構：所有步驟串聯，一個錯全部停擺

二、標準異步架構的四大元件

1️⃣ 管理池（Manager Pool）

職責：
• 創建任務，分配 task_id
• 立即返回給客戶端（不等執行）
• 追蹤任務狀態
• 管理任務的生命周期

不處理實際工作，只管「誰做完什麼」

2️⃣ 任務池（Worker Pool）

職責：
• 從佇列取任務
• 執行具體步驟
• 按負載彈性擴展

特點：
• 失敗不影響其他任務
• 可以分配不同資源給不同任務
• 第三方服務慢就多投放資源

3️⃣ 消息佇列（Message Queue）

職責：
• 任務的暫存和路由
• 確保任務只被處理一次
• （exactly once delivery）

代表工具：
• RabbitMQ（功能豐富）
• Kafka（高吞吐量）
• Redis Queue（輕量）

4️⃣ 重試池（Retry Pool）

職責：
• 專門處理失敗任務的重新執行
• 第三方服務故障時，讓任務等著
• 恢復後全力清理堆積

實作方式：
• 固定頻率重試
• 指數退避（Exponential backoff）
• 獨立出來，不浪費正常任務池資源

五、實作工具比較

工具 類型 特點 適用場景
RabbitMQ 消息佇列 功能豐富、routing 靈活、exactly once delivery、完整權限管理 中小型系統，需要豐富功能的企業應用
Apache Kafka 事件流平臺 高吞吐量、持久化、分區、可擴展 大規模數據流、日志收集、事件驅動
Redis Queue 輕量佇列 簡單、快速、天然適配快取生態 小型系統，快速原型，不需要完整 MQ 功能
Postgres notify/listen 事件驅動（DIY） 不需要額外服務，用現有資料庫實現基本事件機制 已經在使用 Postgres，不想引入新服務
ROS Action 輕量級異步請求 Goal/Feedback/Result 三件套，內建取消機制 機器人控制，導航，操作等長時間運行任務

七、最小化實作：用 Postgres DIY

用 Postgres notify/listen + 觸發器 實現基本事件驅動
┌──────────────────────────────────────────────────────┐
│                 Postgres 事件驅動                      │
├──────────────────────────────────────────────────────┤
                                                      │
│  ┌──────────────┐    ┌────────────┐                   │
│  │   任務表     │    │  觸發器    │                   │
│  │ tasks       │───→│ Trigger   │──→notify channel   │
│  │             │    │           │                   │
│  └──────────────┘    └────────────┘                   │
│                              │                        │
│                              ↓                        │
│                    ┌────────────────┐               │
│                    │ LISTEN channel │──→ 任務池 Worker│
│                    └────────────────┘               │
│                                                      │
│  SQL 示例：                                          │
│                                                      │
│  -- 新增任務（觸發 notify）                          │
│  INSERT INTO tasks (payload) VALUES (...)           │
│    RETURNING id;                                     │
│                                                      │
│  -- Worker 端                                        │
│  LISTEN task_channel;                                │
│  WHILE TRUE:                                         │
│    WAITNOTIFY task_channel;                          │
│    取出待處理任務 ──→ 執行 ──→ 更新狀態             │
└──────────────────────────────────────────────────────┘
📋 標準異步架構核心原則：

1. 任務即創建即返回 — 不等執行，馬上拿 task_id
2. 步驟解耦 — 每個步驟獨立，不連鎖失敗
3. 管理/執行分離 — 管理池只負責追蹤，任務池負責執行
4. Retry 獨立 — 失敗任務進重試池，不耗費正常任務資源
5. 消息佇列 — 任務的暫存和路由，確保可靠傳遞

選擇建議：
- 簡單需求：Postgres notify/listen 有時就夠用
- 中小型：Redis Queue 或 RabbitMQ
- 大規模高吞吐：Apache Kafka
- 機器人控制：ROS Action
