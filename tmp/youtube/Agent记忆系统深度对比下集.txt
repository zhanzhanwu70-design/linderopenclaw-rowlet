我們一個一個猜
我們先從 MAMOS 開始
MAMOS 全稱 Memory Operating System 當前版本為 2.0.8
代號叫星辰 是 MAMPENCER 團隊聯合上海交通大學
這將大學等機構開發的
有一篇 39 位作者署名的學術論文
這個規模在開源記憶項目裡是最大的
那 MAMOS 要解決什麼問題
一句話概括 現有的記憶系統
只是帶檢索功能的存儲庫
解決了記憶放在哪裡的問題
但沒有解決記憶由誰管理 怎麼調度 怎麼演化的問題
MAMOS 的核心主張是
記憶不應該只是一個被動的數據庫
它應該是一個主動治理的操作系統及資源
就像你的電腦有內存管理 有顏面置換 有進程調度一樣
AI 的記憶也需要類似的系統機管理
這個類比不是隨便說說的
MAMOS 的架構確實是按操作系統來設計的
它有六層架構 從上到下分別是
API 接口層
MOS Core 核心引擎
MAMSKIDERAL 一部調度器
MAMCube 記憶容器
MAMERY 記憶存儲層
以及底層的基礎設施層
其中 MOS Core 對應操作系統內核
MAMSKIDERAL 對應進程調度器
MAMCube 對應容器
這套對應關係是完整的
但 MAMOS 最大的差異化特色
不再架構層次本身
而在它的三類記憶體系
我們展開看
MAMOS 把記憶分成了三種形態
文本記憶 激活記憶 和參數記憶
文本記憶是最成熟的部分
它包括簡單文本記憶
基於相量數據庫的通用文本記憶
基於 Neo4J 圖數據庫的數型結構記憶
以及用戶偏好記憶
其中數型記憶是最有特色的設計
激活記憶指的是 KVCash 記憶
原理是把高頻的記憶上下文
預編碼為 KVCash
這樣後續推理的時候
可以跳過重複的 Prefo 計算
直接附用之前編碼好的注意力緩存
MAMOS 支持 Hugging Face Transformers
Dynamic Cache 和 VLM Page Attention 兩種實現
參數記憶是設計藍圖中最有野心的部分
將高頻穩定知識真流為 LoRa 權重
推理時零 token 消耗
但這裡有一個重要的事實
目前代碼裡參數記憶的 Dawn 方法
寫入的是字面量 Placeholder
也就是說它還只是一個站位符
這意味著 MAMOS 化的三元組架構實際上缺了一角
數型記憶分三層
Walking Memory 上限 20 條
Long Term Memory 上限 1500 條
User Memory 上限 480 條
這裡有幾個反直覺的設計細節值得注意
第一
Walking Memory 到 Long Term Memory 不是晉升關係
當 Memory者從對話中提取出一條
Long Term Memory 類型的記憶時
它會同時在 Walking Memory 和 Long Term Memory
各創建一個節點
Walking Memory 只是一個臨時鏡像
用於快速可見
它有 FIFO 淘汰機制
第二
記憶的層次歸屬不是由 Memory Manager 決定的
而是完全由上游的 Memorider 一個 LLM 驅動的組件
通過 Prompt 來判斷的
Memory Manager 本身只是一個中時的執行者
這和你對操作系統調度器
應該做決策的直覺是相反的
再來看調度引擎
MemScheduler 是一個生產級的一部調度引擎
它用 Rated Streams 做內部任務對列
Rabbit MQ 做跨進程消息廣播
現成時最大 30 個 Walker
支持五種任務類型的一部處理
性能方面
MemOS 在四個主要基準上的數據很亮眼
Lokomo 綜合得分 75.80 分排第一
Long MemEval 想比 OpenAI Memory 提升了 40%
偏好個性化評測 Prefab Eval 10 提升了 2568
不過這個 2568 需要冷靜看待
它不是 MemOS 有多強
而是 OpenAI Memory 等機線在偏好個性化上幾乎完全無效
基數極低才導致百分比極高
MemOS 的亮點很多
三類記憶的框架設計在同類產品中最全面
組件可插拔性極高
用了大量工廠模式 有完善的評測體系
但不足也明顯
Lora 記憶只是站為符 完整部署 需要 Neo4j
Q-Drant Redis Rabbit MQ MySQL 五套基礎設施
在我看來 MemOS 的最大價值不在於它當前的工程完成度
而在於它提出的範時
把記憶當作操作系統的一等公民資源來治理
這個方向本身是有說服力的
論文裡有一句話我很認同
就像深度學習替代了特徵工程
記憶管理從硬編碼管道 向可學習策略的轉變
是自然且必要的
但從 8.7 萬多航代碼和五套基礎設施依賴來看
這個操作系統的運位成本也不低
接下來我們看 Open Viking
這是自行跳動旗下火山引擎團隊開源的項目
Apache 2.0 許可
如果說 MemOS 是用操作系統來引誘記憶管理
那 Open Viking 的引誘更接地氣
它用的是文件系統
Open Viking 給自己起了一個新的品類名
上下文數據庫
Context Database
它的核心主張是
Agent 需要管理的不只是記憶
還有資源和技能
而這三類東西
可以統一印射到一個虛擬文件系統裡
具體來說 Open Viking 涉及了一個基於 Viking 協議的虛擬文件系統
把所有上下文組織成三個目錄
Resources 目錄存放導入的外部知識
UZR 目錄存放用戶相關的記憶和偏好
Agent 目錄存放Agent 自身積累的技能和任務記憶
Agent 可以像操作本地文件一樣
操作這些上下文
ls3,Find,Grab,MKDR,RM,MV
這些標準文件系統操作全部支持
這裡有一個很有意思的論點
LLM 在訓練數據中接觸了海量的下要教程
Unix 手測業
它已經深度內化了文件系統的操作語意
相比讓LLM 理解項量數據庫的搜索接口
讓它執行ls和tree反而更自然
而且文件系統的目錄層級是顯示的可解釋的
你看到路徑就知道上下文的組織結構
這比效量數據庫的餘嫌距離要直觀的多
接下來講Open Viking 最核心的技術創新
L0,L1,L2分層上下文加載
每個上下文節點自動生成三層內容
L0 是大約100個token的一句話摘要
L1 是大約2000個token的核心蓋欄
L2 是完整的原始數據
解鎖時採用L0 First 的策略
先看20個候選節點的L0摘要
大約2000個token
然後對高相關的追加LE 蓋欄
大約4000到6000個token
對比傳統RAG每次淘寶檢索要消耗2500個token
時論對話就是25000個token
Open Viking 的token成本可以降低92%到96%
這個數字確實很驚人
但如果你理解了分層加載的負利效應
在常識任務中確實是可以實現的
代價是每次檢索至少多一輪LOLM 調用
增加0.5到2秒延遲
但對於以分中計的Agent 任務來說
幾秒延遲可以忽略
檢索算法也很有意思
Open Viking 用了一個優先級對列
驅動的最佳優先搜索
類似 A 新算法的思路
傳統的 BFS 不加選擇均勻展開
三層十個字幕路就要展開100個節點
DFS 又過於專注某一條路徑
Best First Search 始終選最高分的節點展開
搜索預算優先分配給最有希望的方向
它還有一個分數傳播機制
字節點的最終得分是自身與意相關性
和複節點得分的加權平均
默認權重各佔一半
這個0.5的系數是一個最大商的安全默認值
在信息不充分時不偏向任何一方
用文件系統管記這個思路
你覺得靠譜嗎
靠譜扣1 不靠譜扣2
Open Viking 的工程實現也值得一說
它用了四種變成語言
Python 做核心業務邏輯
C++ 做高性能效量引擎
通過 PyBand 的 11.0 拷貝調用
Go 做文件系統服務器
Rust 做 CLI 工具
每一種語言都是精準的用在了它最擅長的場景
C++ 的相量計算配合 SIMD
優化比純Python 快10~50倍
Go 的 Gorytine 並發模型天然適合文件系統服務
Rust 給 CLI 提供內存安全保證和極快的啟動速度
不過這也意味著你要同時安裝四種語言的工具鏈才能編譯項目
開發環境的搭建成本不低
在我看來 Open Viking 的核心價值在於兩點
文件系統範式讓解鎖過程從黑盒變成了可視化的路徑軌跡
L0 L1 L2 分層讓 Token 成本大幅下降
但項目還處於 0.1.X 早期階段
ReRank 功能標記為 TODO 還沒實現
這意味著當前的效果是在沒有 ReRank 的情況下達成的
後續還有提升空間
另外火箱引擎 SDK 是非可選依賴
即使你只用 Open I 也必須安裝
這暗示了它內部工具開源化的本質
好 接下來是 Hansight
這個項目來自 Vectorize MIT 許可有論文支撐
最關鍵的一個成就是
在 Long-Mem Eval 基準上取得了當前最優的 SOTA 性能
而且經過福吉尼亞理工大學和華盛頓郵報的獨立驗證
Hansight 核心設計哲學用一句話就能說清楚
讓 Agent 學習而不僅僅是記住
這不是口號
它在架構層面做出了真正的區分
Hansight 的記憶架構有明確的認知科學印射
World Fact 對應心理學中的語意及客觀世界知識
比如火爐會很燙
不依附於特定經歷
Experience Fact 對應情景記憶
Agent 的親身經歷
包含 What, When, Where, Who, Why 五個維度
Mental Models 對應程序性知識或專家知識
通過反思形成的綜合理解
比如這個用戶偏好函數式編程模式
還有一個中間層叫 Observations
由 Consolidation 引擎自動從原始事實中提煉出來
介於事實和新製模型之間
為什麼三層優於傳統 RAG
傳統 RAG 把所有信息平鋪為項量
信息層次被壓縮了
Hansight 允許按層次檢索
先查Mental Models 或取綜合理解
再查 Observations 或取提煉模式
最後查 Experience Facts 或取原始事件
這模擬了人類的認知過程
先調用概念模型再回憶具體細節
Hansight 定義了三個核心操作
Retain 存儲記憶
Recall 檢索記憶
Reflect 反思記憶
Retain 的寫入流水線非常驚喜
輸入內容先分快
然後 LLM 提取結構化事實
接著做實體解析和消奇
生成 Inviting 項量
創建四種鏈接
實體鏈接 語意鏈接 時間鏈接和英國鏈接
最後持久化到 PostgreSQL 並觸發 Consolidation
事實提取這個步驟是最 LLM 密集的環節
對應的代碼文件單個就有 2097 行
Recall 檢索使用四路並行策略
語意檢索用 PG Vector
BMR5 全文檢索用 PG Trigram
MPFP 圖檢索是自言原創算法
時間檢索將時間作為獨立檢索維度
這四路不是用於設計
每一路解決的是不同類型的查詢盲區
語意檢索對錯字變化乳棒
但對精確名稱匹配弱
BMR5 對精確詞彙高精度
但對同意詞召回率低
MPFP 圖檢索能發現語意檢索
無法發現的隱性關聯
舉個例子
Alice 因感冒請假和團隊會議缺少關鍵人員
這兩條記憶的語意相似度很低
效量檢索幾乎不可能把他們關聯起來
但通過 MPFP 的實體鏈接和時間鏈接
他們可以被強關聯到一起
MPFP 的全稱是 "Medipath Forward Push"
融合了易購信息網絡的 "Medipath" 模式
和近似 PPR 的 "Forward Push" 局部傳播
它有四種 "Medipath" 模式並行運行
通過共同實體關聯的
通過因果鏈追溯的
通過語意相似關聯的
通過時間窗口鄰近關聯的
關鍵特性是
次線性時間複雜度與圖規模無關
而且便利過程中不需要任何 LLM 調用
思路檢索的結果
通過 RF 融合
然後用 Cross-encoder 做重排序
整個融合使用等權 RF
沒有做查詢自適應的動態權重調整
但依然取得了 SOTA
這說明有時候朴素的方法
反而更魯邦
接下來是實現學習的關鍵
Consolidation 引擎
Retain 完成後
Consolidation 引擎作為後台任務
一步出發
從新寫入的事實中

這個過程和人類睡眠期間的記憶鞏固
有功能類比
後台一步相當於睡眠期間的
非干擾性整合
新事實與現有 Observations 對比
相當於海馬體與新皮層的知識協商
Experience Facts
The Observations 的決話
相當於情景記憶到與意記憶的轉化

每個維度 1 到 5 分

就會產生截然不同的反思結論
比如高懷疑 低字面 低共情
就是一個批判分析型的 Agent
低懷疑 高字面 高共情
就是一個支持陪伴型的 Agent
一套支持庫支持多種應用場景
不需要複製數據
Hansight 的主要局限在於三點

可維護性堪憂
