## 本機實測曝險（本機 = amr-Nitro-AN515-58）
**命中！** 閘道器跑在 `/home/amr/.nvm/versions/node/v24.19.0/bin/node` → 落在受影響的 24.x 且 < 24.22.1。

驗證手法（比對 patched / vulnerable）：
```
node -p "require('zlib').constants.BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH"
# v24.19.0 / v24.14.1 / v20.19.6 → undefined（易受攻擊）
# v24.22.1                      → -17（已修）
```
（npm 套件層級的 brotli 更新救不了這個 — decoder 是編譯進 node binary 的，必須換 runtime。）

**曝險路徑釐清（重要）**：openclaw dist 內的 `createBrotliDecompress` 全部在 **outbound response 解壓**路徑
（`src-_U2rkvQ5.js` 的 `codings === "br"` 分支、`dist-dId8mxfl.js` undici response、worker/worker.mjs 的
`createDecompressInterceptor`），**不是 inbound request body**。所以觸發條件是：
agent 端對外抓取（web_fetch / plugin 下載 / model API）拿到攻擊者可控的 `Content-Encoding: br` 回應，
在 gateway 進程內解壓 → 記憶體破壞 → 以 gateway 使用者權限 RCE。攻擊者只需誘導 agent 造訪惡意網址即可觸發。
