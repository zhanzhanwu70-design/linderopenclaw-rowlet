## 🌿🦉 Minerva HC #19：Deductions（演繹法）

### 定義

**Deduction（演繹推理）** — 從**一般前提**必然推出**特殊結論**的推理方式。形式邏輯的基石。

核心三特徵：
1. **方向**：一般 → 特殊（general → particular）
2. **必然性**：如果前提為真，結論**必然**為真（≠ 可能為真）
3. **保真性**：前提真 ⇒ 結論真（truth-preserving）

> **一句話**：演繹是「把前提中的訊息**展開**出來」，不創造新事實。

形式符號：$P_1, P_2, \ldots, P_n \vDash C$（前提蘊含結論）

**經典三段論**：
- 大前提：所有人會死
- 小前提：蘇格拉底是人
- 結論：蘇格拉底會死 ✓

---

### 為什麼這個 HC 重要？

Deduction 是所有**形式系統**的根：數學證明、程式語言型別系統、法律三段論、資料庫查詢、形式化驗證、LLM 的 chain-of-thought 拆解。沒有演繹素養，就分不清「論證形式有效」和「結論為真」——這是哲學家、科學家、工程師都會犯的錯。

> 演繹出錯不是運氣差，是**結構崩壞**——而 LLM 是這方面的高風險族群。

---

### 核心區分：Validity vs Soundness

這是 Deduction 最重要的概念，沒掌握就不算學會這個 HC：

| 概念 | 定義 | 結論是否保真 |
|------|------|------------|
| **Valid（有效）** | 形式正確：前提真 ⇒ 結論必然真 | **前提都真時**保真 |
| **Sound（健全）** | Valid **且** 前提都為真 | 結論**一定為真** |
| **Invalid（無效）** | 形式錯誤：可能前提真但結論假 | — |
| **Unsound（不健全）** | Invalid 或前提不真（或兩者） | 結論可能為假 |

**關鍵警句**：
> ❌ 「這個論證有效，所以結論是對的」
> ✅ 「這個論證有效，但前提是否為真是另一個問題」

**經典反例**：
- 大前提：所有魚都會飛（假）
- 小前提：鯨魚是魚（真）
- 結論：鯨魚會飛（假）

**這是 Valid 但 Unsound**——形式完美，前提有毒。在 LLM 上極常見：推理鏈結構漂亮，但第一步假設就是錯的。

### 演繹推理形式速查

#### 命題邏輯（Propositional Logic）

| 規則 | 形式 | 有效性 | 日常語言範例 |
|------|------|--------|------------|
| **Modus Ponens（肯定前件）** | P→Q, P ⊢ Q | ✅ 有效 | 天下雨→地濕，天下雨，∴ 地濕 |
| **Modus Tollens（否定後件）** | P→Q, ¬Q ⊢ ¬P | ✅ 有效 | 天下雨→地濕，地不濕，∴ 沒下雨 |
| **Hypothetical Syllogism** | P→Q, Q→R ⊢ P→R | ✅ 有效 | A→B, B→C, ∴ A→C |
| **Disjunctive Syllogism** | P∨Q, ¬P ⊢ Q | ✅ 有效 | 咖啡或茶，不喝咖啡，∴ 喝茶 |
| **Affirming the Consequent（肯定後件）** | P→Q, Q ⊢ P | ❌ 無效謬誤 | 天下雨→地濕，地濕，∴ 天下雨（灑水器也會） |
| **Denying the Antecedent（否定前件）** | P→Q, ¬P ⊢ ¬Q | ❌ 無效謬誤 | 天下雨→地濕，沒下雨，∴ 地不濕（灑水器） |

#### 類別邏輯 / 三段論（Categorical Syllogism）

| 形式 | 範例 | 有效性 |
|------|------|--------|
| **Barbara (AAA-1)** | All M are P, All S are M ⊢ All S are P | ✅ 有效 |
| **Darii (AII-1)** | All M are P, Some S are M ⊢ Some S are P | ✅ 有效 |
| **Undistributed Middle** | All A are C, All B are C ⊢ All A are B | ❌ 無效 |
| **Illicit Major** | All A are B, No C are A ⊢ No C are B | ❌ 無效 |

**Undistributed Middle 範例**（超常見的錯）：
- 大前提：所有貓是哺乳動物
- 小前提：所有狗是哺乳動物
- 結論：所有貓是狗 ✗

「哺乳動物」這個中項沒被「分配」（distribute）到全部範圍，所以推不出。

### 真值表（Truth Table）分析

判斷命題邏輯有效性的**機械化方法**：

```python
from itertools import product

def is_valid(premises, conclusion, variables):
    """
    檢查論證是否有效：對所有變數賦值，
    如果存在「前提全真但結論為假」的情況，則無效。
    """
    counterexamples = []
    for assignment in product([False, True], repeat=len(variables)):
        env = dict(zip(variables, assignment))
        if all(eval(p, env) for p in premises) and not eval(conclusion, env):
            counterexamples.append(env)
    return len(counterexamples) == 0, counterexamples

# 測試 Modus Ponens: P→Q, P ⊢ Q  (有效)
valid, ce = is_valid(["P and (not P or Q)", "P"], "Q", ["P", "Q"])
print(f"Modus Ponens valid? {valid}")  # True

# 測試 Affirming Consequent: P→Q, Q ⊢ P  (無效)
valid, ce = is_valid(["(not P or Q)", "Q"], "P", ["P", "Q"])
print(f"Affirming Consequent valid? {valid}, counterexample: {ce}")
# False, counterexample: {'P': False, 'Q': True}
```

**八種基本真值表運算**：

| P | Q | ¬P | P∧Q | P∨Q | P→Q | P↔Q | P⊕Q |
|---|---|----|----|----|----|----|----|
| T | T | F | T | T | T | T | F |
| T | F | F | F | T | F | F | T |
| F | T | T | F | T | T | F | T |
| F | F | T | F | F | T | T | F |

### 實作方式

#### 方式一：sympy 邏輯推理

```python
from sympy import symbols, Implies, And, Or, Not, satisfiable
from sympy.logic.inference import valid

P, Q, R = symbols('P Q R')

# 檢查 Modus Ponens 有效性
premises = [Implies(P, Q), P]
conclusion = Q
print(valid(conclusion, premises))  # True

# 檢查 Affirming Consequent
premises = [Implies(P, Q), Q]
conclusion = P
print(valid(conclusion, premises))  # False

# 找反例
list(satisfiable(And(Implies(P, Q), Q, Not(P))))  # [{P: False, Q: True}]
```

#### 方式二：自然語言→邏輯→驗證（LLM 鏈推理）

```python
def check_argument(premises_nl, conclusion_nl):
    """
    簡化版：人類寫 NL 前提/結論，
    LLM 翻成邏輯，再用 sympy 驗證。
    """
    # 步驟 1: LLM 提取命題
    props = llm_extract_propositions(premises_nl)  # e.g. ["P -> Q", "P"]
    conclusion = llm_to_logic(conclusion_nl)  # e.g. "Q"
    
    # 步驟 2: 形式化驗證
    is_valid = check_validity(props, conclusion)
    
    # 步驟 3: 回報 soundness
    premises_true = llm_check_premises_truth(props)
    return {
        "valid": is_valid,
        "premises_true": premises_true,
        "sound": is_valid and all(premises_true),
        "verdict": "✓ sound" if is_valid and all(premises_true)
                  else "⚠ valid but unsound" if is_valid
                  else "✗ invalid"
    }
```

```python
from z3 import *

x, y = Ints('x y')
s = Solver()
s.add(ForAll([x, y], Implies(
    And(x > 0, y > 0),
    x * y > 0
)))
print(s.check())  # sat — 證明成立
```

#### 方式五：Chain-of-Thought 驗證（LLM 評測）

```python
def cot_deduction_check(prompt, expected_steps, model):
    """
    評測 LLM 演繹推理：用 CoT 強制逐步推理，
    檢查每步是否為有效推論。
    """
    response = model.generate(prompt + "\nLet me reason step by step:")
    steps = parse_steps(response)
    
    for i, (premise, conclusion) in enumerate(zip(steps, steps[1:])):
        if not is_valid_inference(premise, conclusion):
            return {"valid_chain": False, "failed_step": i}
    return {"valid_chain": True, "conclusion": steps[-1] == expected_steps[-1]}
```

### 應用場景

| 場景 | 演繹扮演的角色 | 注意事項 |
|------|---------------|---------|
| **數學證明** | 從公理 + 已知定理推出新定理 | 每步必須是 valid inference |
| **法律三段論** | 法條（大前提）+ 案情（小前提）→ 判決 | 經典 Common Law 推理 |
| **型別系統 / 編譯器** | 程式語意推導 | Hindley-Milner, dependent types |
| **資料庫查詢** | Relational Algebra 是演繹的 | SQL WHERE 條件 = 邏輯公式 |
| **知識圖譜 / 描述邏輯** | OWL, RDF 推理 | 醫療、金融知識本體 |
| **Formal Verification** | 證明程式/硬體正確性 | 航太、晶片、密碼協議 |
| **LLM Chain-of-Thought** | 拆解推理步驟讓 LLM 跟著推 | 仍非 100% 可靠演繹 |
| **自動定理證明** | 純演繹系統（Lean, Coq）| 用於形式化數學 |

---

### LLM 場景的特殊挑戰

LLM **不執行演繹**，是**模仿演繹的文字**。常見失敗模式：

| 失敗模式 | 範例 | 解法 |
|---------|------|------|
| **肯定後件謬誤** | "他說謊所以他是壞人" | 加 explicit inference check |
| **拼字正確但前提假** | "所有工程師都會寫 Python" | 預先驗證前提 |
| **Circular reasoning** | 結論被藏在前提 | 反向檢查 |
| **跳步** | A→C，但跳過 B→C | 強制逐步驟生成 |
| **Inconsistency** | 同時 P 和 ¬P | 抽取知識庫做一致性檢查 |

**實務策略**：
1. **LLM 生成 + 符號驗證器驗證**（LLM-as-proposer, Solver-as-verifier）
2. **Few-shot 演繹範例**（在 prompt 中放 5-10 個 valid inference 範例）
3. **Self-consistency**：多次生成，找最一致的答案

### 與 #20 Logical Fallacies 的關係

#20 嚴格說是 #19 的**反面**：所有演繹謬誤都是**形式無效**的論證。

| #19 學的東西 | #20 提醒的陷阱 |
|------------|--------------|
| Modus Ponens | Affirming the Consequent |
| Modus Tollens | Denying the Antecedent |

### 反思問題

1. 我用的論證是 **valid** 還是 **sound**？前提事實為真嗎？
2. 我有沒有犯 **Affirming the Consequent**？（「A→B，觀察到 B，就說 A」）
3. 中項（M）有沒有被 **distributed**？三段論結構正確嗎？
4. 我是在做**演繹**還是**歸納**？混用的話哪個階段是哪個？
5. LLM 給的推理鏈：每一步都驗過 valid 嗎？前提有沒有外部驗證？
6. 結論是「必然為真」還是「很可能為真」？我搞混了沒？
7. 形式有效但前提假時，我能識別出來嗎？

### 經典陷阱

| 陷阱 | 例子 | 解法 |
|------|------|------|
| 把 valid 當 true | 前提有毒但推理漂亮 | 區分 validity / soundness |
| Affirming consequent | 下雨→地濕，地濕，∴ 下雨 | 改用 Modus Tollens 反推 |
| Denying antecedent | 下雨→地濕，沒下雨，∴ 地不濕 | 承認有其他原因 |
| Undistributed middle | 貓是哺乳動物，狗是哺乳動物，∴ 貓是狗 | 中項必須 distribute |
| 假兩難 | 假設只有 P 和 Q | 列舉所有可能 |
| 循環論證 | 用結論證前提 | 找外部錨點 |
| 滑動斜率 | 偷換前提範圍 | 鎖定前提措辭 |
| 稻草人 | 攻擊扭曲後版本 | 鎖定原命題 |
| 訴諸權威 / 情感 | 用名氣或情緒代替推理 | 要求純形式驗證 |
| LLM 幻覺推論 | 看起來合理的推論鏈 | 符號驗證器外部檢查 |

### Deduction 的極限（誠實補充）

Deduction 不是萬能：

| 限制 | 說明 |
|------|------|
| **垃圾進、垃圾出** | 前提假 → 結論假（valid 救不了）|
| **不能創造新事實** | 只展開既有訊息，所有科學突破都靠歸納 + 演繹 |
| **前提選擇是歸納** | 「用哪些前提」本身就是歸納判斷 |
| **現實前提不完美** | 數學演繹乾淨，但經驗問題前提都是概率性的 |
| **形式化成本高** | 完整形式驗證極貴，多用於 critical systems |

> 牛頓、達爾文、愛因斯坦的突破**不靠演繹**，靠**演繹 + 歸納 + 直覺 + 實驗**的循環。

---

**為何這個 HC 重要**：所有結構化推理的脊椎。沒學會 validity / soundness 區分，就會被「聽起來合理其實謬誤」的論證說服——不管那論證來自人還是 LLM。

下次看到一段論證（自己的、對手的、LLM 的），先問三句：
> 「形式 **valid** 嗎？」
> 「前提都 **true** 嗎？」
> 「所以這是 **sound** 嗎？」
