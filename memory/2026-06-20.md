### TokenMizer: Graph-Structured Session Memory for Long-Horizon LLM Context Management

**arXiv**: [2606.06337](https://arxiv.org/abs/2606.06337)
**Authors**: Shweta Mishra

#### 儲存位置

#### 核心貢獻
1. **Typed Knowledge Graph Schema**: 14 種 node types、7 種 edge types 建模 session history
2. **78 tokens resume blocks**: 比 baseline 的 159-170 小 2x
3. **Decision recall +9-17 pp**: baseline 只保留「技術被提到」，TokenMizer 保留「為什麼」
4. **Fuzzy label matching**: ablation 顯示這是主導改進因子 (+33 pp task recall)
5. **47.3% token reduction**: 零外部依賴壓縮

#### 與現有工作的關係
- StreamingLLM: attention mechanism 層級的 context 管理
- TokenMizer: session 結構化歷史
- 兩者互補，解決不同層次的 context overflow 問題

#### 討論重點（可供團隊討論）
1. 將 session history 建模為 KG vs 扁平的 text summarization——哪種更適合 code agent？
2. Fuzzy label matching +33 pp 的效果很顯著——這是否意味著 schema 設計比 extraction algorithm 更重要？
3. 14 node types 的 schema 是否足以 capture 所有重要的 code agent session 資訊？
4. Three-tier checkpoint system 的 checkpoint 頻率如何決定？
