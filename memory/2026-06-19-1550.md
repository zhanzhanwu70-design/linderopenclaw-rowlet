## 🌿🦉 Minerva HC #21：Induction（歸納法）

### 定義

**Induction（歸納推理）** — 從**特殊觀察**推出**一般結論**的推理方式。所有科學、機器學習、LLM pre-training、日常生活中「看到 A 所以猜 B」都靠它。

核心三特徵：
1. **方向**：特殊 → 一般（particular → general）
2. **概率性**：前提為真 ⇒ 結論**可能**為真（≠ 必然為真）
3. **創造新知**：結論**超出**前提所含資訊（與演繹相反）

> **一句話**：歸納是「從有限樣本**跳出去**猜全貌」，**這個跳躍不保證對，但沒有它就沒有科學**。

形式符號：$O_1, O_2, \ldots, O_n \vdash C$（觀察引出結論，但 $C$ 不被 $O_i$ 邏輯蘊含）

**經典例子**：
- 觀察：這隻天鵝是白的、那隻天鵝是白的、那隻也是...
- 結論：所有天鵝都是白的 ✓（歸納）vs. ✗（被黑天鵝推翻）

> Hume 的歸納問題（1748）：**歸納沒有邏輯必然性**。我們「相信太陽明天會升起」，純粹是**心理慣性**，不是邏輯必然。

---

### 為什麼這個 HC 重要？

歸納是**所有經驗科學的引擎**——沒有歸納就沒有物理學、生物學、社會科學、機器學習。但歸納天生帶**不確定性**，是 #20 謬誤的高發地。

| 場景 | 沒有歸納素養的災難 |
|------|------------------|
| **醫學診斷** | 個案 → 過度概括（hasty generalization），誤判疾病 |
| **政策制定** | 樣本偏差（survivorship bias），只看成功政策不見失敗 |
| **機器學習** | 訓練集偏 → 模型在現實崩潰（OOD failure）|
| **金融投資** | 過去績效推未來（gambler's fallacy 的反向）|
| **日常生活** | 一次塞車就說「這條路每天塞」|
| **AI 對齊** | 從有限 reward signal 推 agent 整體目標（Goodhart's Law）|
| **歷史研究** | 把當代價值觀投射到過去（presentism）|

**心理學實證**：
- 人類歸納傾向極強——3 個樣本就敢下結論（Kahneman, 2011）
- **Availability heuristic** 讓我們用「想得到」代替「真實分布」
- **Representativeness heuristic** 讓我們用「像不像」代替「基率」

### 演繹 vs 歸納：完整對比

| 面向 | Deduction（#19）| Induction（#21）|
|------|----------------|----------------|
| 方向 | 一般 → 特殊 | 特殊 → 一般 |
| 結論 | 必然為真（前提真時）| **可能**為真（永遠有反例風險）|
| 新知 | 無（展開既有）| **有**（從樣本跳出去）|
| 確定性 | 邏輯必然 | 概率 |
| 失敗模式 | 形式錯 / 前提假 | 樣本偏 / 過度概括 |
| 範例 | 數學證明、邏輯推論 | 科學實驗、ML 訓練 |
| Hume 評價 | 邏輯必然 | 心理慣性 |
| Popper 評價 | 可證偽 | — |
| AI 範例 | Lean, Prolog | 統計學習、LLM |

> **關鍵洞察**：所有 #20 歸納謬誤都是 #21 的失敗模式。學 #21 = 理解「為什麼會犯 #20 那批錯」。

### 歸納推理類型譜系（從弱到強）

```
歸納強度譜
├── 1. 枚舉歸納（最弱）         # 觀察 N 個都 P → 全部 P
│      → 只需 1 個反例推翻
│
├── 2. 類比歸納                # A 有 P, B 似 A → B 有 P
│      → 依賴相似性判斷
│
├── 3. 統計歸納                # 樣本比例 → 母體比例
│      → 依賴抽樣隨機性
│
├── 4. 因果歸納                # A 與 B 相關 → A 致 B
│      → 還需 confounding 控制
│
├── 5. 機制歸納（最強）         # 從理論機制解釋觀察
│      → 為相關找到因果
│
└── 6. 貝氏歸納                # 先驗 + 證據 → 後驗
       → 動態更新
```

#### 各類型範例

| 類型 | 觀察 | 結論 | 強度 | 主要風險 |
|------|------|------|------|---------|
| **枚舉歸納** | 1000 隻白天鵝 | 所有天鵝白 | 弱 | 1 隻黑天鵝推翻 |
| **統計歸納** | 60% 樣本支持 | 母體 60% 支持 | 中 | 樣本非隨機 |
| **類比歸納** | 火星似地球，地球有水 | 火星有水 | 弱 | 相似度判斷主觀 |
| **因果歸納** | 抽煙者肺癌率高 | 抽煙致肺癌 | 中 | 可能有基因混淆 |
| **機制歸納** | DNA 損傷→細胞突變→癌 | 抽煙致肺癌（生化路徑）| 強 | 機制可能錯 |
| **貝氏歸納** | 新試驗結果 | 更新後驗機率 | 動態強 | 先驗選擇主觀 |

### Hume 的歸納問題（哲學地基）

**David Hume（1748, *An Enquiry Concerning Human Understanding*）**：

> 歸納的合理性**不能**用歸納論證（這會循環）。
> 歸納的合理性**不能**用演繹論證（前提不蘊含結論）。
> 所以歸納的合理性是**心理習慣**，不是邏輯。

**Hume 的拆解**（用 #20 的語言重述）：
- 前提：「過去太陽每天升起」（100% 觀察）
- 結論：「太陽明天會升起」
- 推理形式：枚舉歸納
- 反例風險：明天太陽可能被超新星吞噬
- **結論**：歸納的信心**純粹是習慣**，沒有邏輯基礎

**回應方式**（20 世紀哲學）：
1. **Popper（否證主義）**：科學不靠歸納，靠**猜想 + 否證**
2. **Carnap（歸納邏輯）**：用數學定義「確認度」c(h, e)
3. **Bayesian**：用貝氏定理把歸納變成機率更新
4. **Goodman（新歸納之謎）**：歸納依賴「投射性」（projectibility），不是所有性質都能歸納

> **現代理性觀**：歸納**不完美但必要**。承認 Hume 問題的同時，用 Bayesian + pre-registration + replication 把歸納風險量化。

### 實作方式

#### 方式一：樣本評估（最基本）

```python
def evaluate_induction(sample: list, hypothesis: str) -> dict:
    """
    評估一個歸納的強度
    """
    n = len(sample)
    if n < 30:
        confidence_penalty = "⚠️ 樣本過小，結論不可靠"
    
    return {
        "n": n,
        "sample_diversity": check_diversity(sample),  # 多樣性
        "sample_randomness": check_randomness(sample),  # 隨機性
        "counter_evidence_searched": True,  # 是否主動找反例
        "mechanism_provided": has_mechanism(hypothesis),  # 是否有機制解釋
        "confidence": compute_confidence(sample, hypothesis)
    }

def check_diversity(sample):
    """檢查樣本是否覆蓋不同情境"""
    contexts = set([s.context for s in sample])
    return len(contexts) / len(sample)  # 多樣性比例
```

#### 方式二：貝氏歸納（現代標準）

```python
import numpy as np
from scipy import stats

def bayesian_induction(prior: dict, evidence: list) -> dict:
    """
    貝氏歸納：先驗 + 證據 → 後驗
    """
    # 範例：硬幣是否公平
    # prior: {"fair": 0.5, "biased": 0.5}
    # evidence: [H, H, T, H, H, H, T, H, H, H]  # 10 次投擲
    
    # 似然
    p_evidence_given_fair = 0.5 ** len(evidence)
    
    # 假設 biased: 用 Beta(α, β) 估計
    alpha, beta = 1 + sum(e == 'H' for e in evidence), 1 + sum(e == 'T' for e in evidence)
    p_evidence_given_biased = stats.beta.pdf(0.5, alpha, beta)
    
    # 後驗（簡化版）
    posterior_fair = prior['fair'] * p_evidence_given_fair
    posterior_biased = prior['biased'] * p_evidence_given_biased
    total = posterior_fair + posterior_biased
    
    return {
        "posterior_fair": posterior_fair / total,
        "posterior_biased": posterior_biased / total,
        "verdict": "fair" if posterior_fair > posterior_biased else "biased"
    }
```

**為什麼貝氏強於純枚舉**：
1. 自動量化**不確定性**
2. 先驗承載**領域知識**
3. 新證據**動態更新**
4. 避免過度概括（後驗永遠 < 100%）

#### 方式三：實驗設計（Mill 的方法）

**John Stuart Mill（1843, *A System of Logic*）** 提出五個歸納法則：

| 方法 | 描述 | 應用 | 風險 |
|------|------|------|------|
| **MILL 1：求同法（Method of Agreement）** | 找出所有案例的共同因素 | 比較 100 個肺癌患者，發現都吸煙 | 可能漏掉共同原因 |
| **MILL 2：求異法（Method of Difference）** | 比較有/無結果的案例差異 | 吸煙 vs 不吸煙：肺癌率差異 | 可能有混淆變項 |
| **MILL 3：同異聯合法（Joint Method）** | 結合 1 + 2 | 多組對照 | 樣本設計複雜 |
| **MILL 4：剩餘法（Method of Residues）** | 排除已知因素後剩下的 | 行星軌道異常 → 海王星 | 假設其他因素已正確 |
| **MILL 5：共變法（Method of Concomitant Variation）** | 觀察 A 變 B 也變 → 相關 | 劑量↑ 毒性↑ | 相關 ≠ 因果 |

```python
def mill_method_of_difference(treatment_group, control_group, outcome):
    """
    求異法：比較兩組的差異因素
    """
    # 找出 treatment 有但 control 沒有的因素
    diff_factors = set(treatment_group.factors) - set(control_group.factors)
    
    # 候選因果因素
    candidates = [f for f in diff_factors 
                  if correlates_with(f, outcome)]
    
    return {
        "candidate_causes": candidates,
        "warning": "相關 ≠ 因果，需控制 confounding"
    }
```

#### 方式四：Cross-Validation 與 Bootstrap（ML 標準）

```python
from sklearn.model_selection import cross_val_score, KFold
import numpy as np

def induction_with_cv(model, X, y, k=10):
    """
    歸納（從訓練集推母體）的標準驗證法
    """
    kf = KFold(n_splits=k, shuffle=True, random_state=42)
    scores = cross_val_score(model, X, y, cv=kf, scoring='accuracy')
    
    return {
        "mean_accuracy": scores.mean(),
        "std": scores.std(),
        "ci_95": (scores.mean() - 1.96*scores.std()/np.sqrt(k),
                  scores.mean() + 1.96*scores.std()/np.sqrt(k)),
        "warning": "若 train acc >> val acc：overfitting（過度歸納）"
    }
```

### 在 AI / LLM 場景的應用

| 場景 | 歸納扮演的角色 | 風險 |
|------|--------------|------|
| **LLM Pre-training** | 從 1T tokens 歸納語言模型 | dataset bias 永久編碼 |
| **In-context learning** | 從 few-shot 範例歸納任務模式 | 樣本少 + 任務模糊 → 不可靠 |
| **Fine-tuning** | 從 N 樣本歸納 → 模型參數 | catastrophic forgetting（小樣本破壞大能力）|
| **RLHF** | 從人類偏好歸納 reward model | reward hacking |
| **RAG** | 從檢索片段歸納答案 | 若片段偏，結論偏 |
| **Chain-of-thought** | 從範例歸納推理模式 | 可能學到錯誤啟發式 |
| **Self-consistency** | 多路徑歸納 → 多數決 | 錯的共識還是錯 |
| **Constitutional AI** | 從原則歸納行為 | 原則的歸納本身有偏 |

**LLM 特有的歸納謬誤**：

| 謬誤 | 描述 | 解法 |
|------|------|------|
| **Few-shot over-generalization** | 3 個範例 → 永遠這樣 | 加大樣本 + 明確指令 |
| **Pattern matching without understanding** | 形式像 → 結論同 | 加機制解釋 + 反例 |
| **Anchoring on training distribution** | LLM 用 pre-training 經驗推斷 | RAG + 外部驗證 |
| **Sycophantic induction** | 「用戶說的應該是真的」 | 反向歸納：先找反例 |
| **Confidence calibration failure** | 高頻信心詞 ≠ 真實機率 | temperature + uncertainty tokens |
| **Distribution shift blindness** | 訓練分布推測試分布 | OOD detection |

### 反思問題

1. 我這個結論是**演繹**還是**歸納**？混用了嗎？
2. 我的樣本**多大**？**多樣**？**隨機**？
3. 我有沒有**主動找反例**？還是只看到支持證據？
4. 我的歸納是**枚舉 / 統計 / 類比 / 因果 / 機制**？哪種？強度夠嗎？
5. 有沒有 **confounding**（第三變項）？控制了嗎？
6. 結論是「**所有**」「**大部分**」「**可能**」哪個？措辭匹配證據強度嗎？
7. **Hume 問題**：我為什麼相信歸納？真的只是習慣嗎？
8. LLM 對話：我有沒有被**幾個範例**就說服了？樣本夠大嗎？
9. 我在**小樣本**下做決策時，風險有量化嗎？（機率 + 信心區間）

| 陷阱 | 例子 | 解法 |

### 歸納的極限（誠實補充）

| 限制 | 說明 |
|------|------|
| **Hume 問題** | 歸納無邏輯必然性，只有心理慣性 |
| **Black swan 風險** | 任何歸納都可能被單一反例推翻 |
| **Goodman 問題** | 不是所有性質都可投射（"grue" paradox）|
| **New riddle of induction** | 歸納的合理性依賴「相似性」概念，相似性本身是歸納來的 |
| **Base rate 問題** | 不查基率 = 永遠做錯機率判斷 |
| **Confirmation bias** | 人會主動找支持歸納的證據，忽略反例 |
| **Publication bias** | 只發顯著結果，歸納池嚴重偏 |
| **P-hacking** | 反覆檢定直到顯著 = 假歸納 |
| **過度擬合** | 樣本規律視為母體規律 |
| **執行成本** | 嚴格歸納（pre-reg, replication）成本極高 |

> **平衡**：歸納**不完美但必要**。**承認 Hume 問題** + **用 Bayesian / pre-reg / replication 量化風險** = 現代科學的實際做法。

---

**為何這個 HC 重要**：#19 演繹告訴你「**前提真 ⇒ 結論真**」，#21 歸納告訴你「**前提真 ⇒ 結論可能真**」。**沒有 #21 的機制理解，你學的 #20 是死背的清單**；沒有 #21 的概率素養，你做不出不確定性決策。

下次做歸納（不論是自己的、科學的、還是 LLM 的），先問三句：
> 「樣本**多大、多樣、隨機**？」
> 「我有沒有**主動找反例**？」
> 「結論措辭**匹配證據強度**嗎（所有 / 大部分 / 可能）？」
