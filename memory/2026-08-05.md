### 重點複習

論文核心：雙層架構解決 context management irreversibility
- Message Maintenance Layer: 存 raw + abstract（lossless，可逆）
- Context Orchestration Layer: 每步動態分配 elastic type (raw/abstract/drop)
- 訓練免費、框架無關（wrapper style）
- 支援 ReAct、DeepAgent、WebThinker、MiroFlow

### 討論重點（3-5 個）

1. **Irreversibility 是根本問題**：現有方法（truncation / summarization / recurrent compression）一旦 discard 就永久失去。ACE 的 lossless maintenance layer 是首個系統性解決這個問題的框架。

2. **Elastic type 分配其實也是 LLM inference cost**：每步由一個 LLM 根據 current task state 決定 elastic type — 這本身有 compute overhead，論文沒有 explicit 討論這個 trade-off。

3. **Wrapper style 的通用性 vs 準確性**：external wrapper 不改框架是好處，但 elastic type 分配的 quality 完全取決於那個 LLM 的判斷能力。如果分配錯誤，效能會受影響。

4. **對 Rowlet 的直接啟發**：三層記憶架構（SOUL/MEMORY + daily memory + wiki）類似 message maintenance layer 的分層思路。可以借鑒「可逆 + 每步動態重建」的原則來改進 heartbeat 的 memory eviction policy。

5. **與其他方法的互補性**：ACE 是 training-free、per-step 的動態方案；CompactionRL 是 training-time learnable compression；SelfMem 是 inference-time self-exploration。三者可以組合。
