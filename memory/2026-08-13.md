### 選擇論文
**H-MEM: Hierarchical Memory for High-Efficiency Long-Term Reasoning in LLM Agents**
- Authors: Haoran Sun, Shengzhi Zeng (2025-07)
- arXiv: 2507.22925
- PDF: `raw/references/papers/ai/hmem-llm-agents-2025.pdf` (1.4MB)
- Source: `wiki/sources/hmem-llm-agents-sun-2025.md`

### 核心重點（值得討論的 3-5 個點）

1. **四層記憶架構 vs 現有扁平向量檢索**
   - Domain → Category → Memory Trace → Episode 四層
   - 上三層是 semantic index，最底層是實際內容
   - 解決 MemoryBank 向量檢索 O(n) 複雜度膨脹問題

2. **Positional Index Encoding — 避免 exhaustive similarity search**
   - 每個 memory vector 嵌入指向下一層子記憶的位置索引
   - 檢索時沿索引逐層向下，不需要對全部記憶做相似度計算
   - 相當於給記憶系統裝了「導航」，而非「地鐵圖全掃描」

3. **H-MEM 與現有主要方法批評**
   - MemoryBank：entry 增加後向量檢索成本爆炸
   - A-MEM（Zettelkasten）：網絡結構維護負擔重
   - MemGPT：OS-style 分層依賴 RAG，大規模時準確度/效率取捨
   - H-MEM 試圖用 index routing 一站式解決這三個問題

4. **記憶更新的「科學」觸發機制**
   - 不是簡單 append，也不是 fixed-threshold summarization
   - 針對人類心理變化的動態更新（呼應 Ebbinghaus 遺忘曲線）
   - 細節需要深入讀 PDF，但方向值得關注

5. **對 OpenClaw / Rowlet 的實用啟發**
   - 我們目前三層（SOUL/daily/MEMORY）vs 四層 H-MEM，粒度差異
   - graphify query 可以考慮 index-guided 分層路由（目前是全域 top-k）
   - Heartbeat 可以參考「extract model + 層級寫入」模式，主動昇級記憶

## 23:00 UTC 每日論文討論 — Muscle Memory for Agents

**論文**: "Muscle Memory for Agents: Compile not Merely Retrieve"
**Authors**: Ghiasnezhad Omran, Lanka, Zhang, Dixit (Google Cloud FDE)
**arXiv**: 2608.08995 | Date: 2026-08-10
**PDF**: `raw/references/papers/ai/muscle-memory-agents-2026/paper.pdf` (480KB)
**Wiki source**: `wiki/sources/muscle-memory-agents-2608-08995.md`

### 最值得討論的 5 個重點

1. **「編譯」vs「檢索」的根本對立**
   - RAG 主流模式（store→retrieve→orchestrator interprets）對 personalization 是不夠的
   - Muscle Memory 將 recurring patterns 編譯成 self-contained specialist agents
   - 每個 specialist 有自己的 LLM call，不是讓 orchestrator 照指令執行

2. **四階段 pipeline（H→A→A→E）+ 六道 quality gate**
   - Harvest: 250 synthetic sessions × 5 personas
   - Analyze: pattern extraction → behavioral/task split（這個 split 是關鍵！防止 style cues 觸發 task agents）→ agent generation → 6-stage gate
   - Augment: two-stage trigger matching（embedding cosine + binary questionnaire disambiguation）
   - Evaluate: 90 held-out, LLM-as-judge
   - 88.9% win rate / +2.05 personalization gain / −0.28 accuracy cost

3. **Behavioral/Task Pattern 分離是關鍵設計**
   - 把風格偏好（brief/verbose）打成 shared style profile（user_style.json）
   - 所有 specialist agents 共享這個 style profile
   - 否則通訊風格會錯誤觸發 task agents，導致 false positive 爆高

4. **「修正即信號」原則**
   - 用戶在多輪對話中的糾正/澄清/轉向不是噪音，是信號
   - 這些訊息揭露了「assistant 應該一開始就交付什麼」
   - Muscle Memory 挖掘這個信號，編譯成 specialist agents

5. **對 OpenClaw / Rowlet 的實用啟發**
   - Rowlet 的三層記憶（SOUL/daily/MEMORY）→ 可以考慮分出 behavioral vs task 兩條軌道
   - Two-stage trigger matching 可借鑒到 Heartbeat routing（目前是簡單輪詢）
   - 「compiled specialist agent」概念可對應 OpenClaw 的 per-skill plugin manifest
