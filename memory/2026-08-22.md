### 為什麼選這篇

昨天（08-21）讀 PLACEMEM 是 **serving-infrastructure 視角**（cross-layer boundary）。今天刻意選一個 **application-layer 但跨 batch-boundary 的工作**，剛好和 PLACEMEM 互補：兩個 paper 從不同 stack layer 解決同一個核心問題（**跨 boundary 的 continuity**）。LycheeMemory V2 同時推進 accuracy + construction cost + query cost 三個 axis（vs A-Mem: +20.4 pp / −86.0% / −27.9%）——是 collection 第一個 Pareto improvement。

### 5 個最值得討論的重點

1. **"Granularity is the lever"**：核心 insight 是 **accuracy–cost trade-off 不只取決於「保留什麼資訊」，也取決於「以什麼粒度 consolidate」**。Turn-level eager consolidation（Mem0/A-Mem）每個 exchange 一次 LLM call；conversation-level 又會丟 fine-grained evidence。**Segment-level 是 sweet spot**——embed-based boundary detector 零 LLM cost 達成 batching 效益，但比 mechanical fixed-window 保留 semantic coherence（cost 幾乎相同但 accuracy +6.8 pp）。

2. **Cost Pareto frontier 真實推進**：LycheeMemory V2 是 collection 中**第一個同時改善 accuracy + construction cost + query cost** 的工作。其他要 trade-off：VISTA 保 fidelity 增 cost、CompactionRL 學 policy 增 train cost、ContextWeaver 增 dependency tracking cost。LycheeMemory V2 用「**segment 一次 encoding 取代 T 次 + plan-guided multi-route 取代 iterative multi-step retrieval**」**同時壓低兩端**。

3. **Cross-segment disambiguation state 是 implicit 的 clever invention**：每個 segment encoding 後回傳 `d_k`（aliases、canonical entity、reference relations），下一個 segment 的 reference context 是 `ρ_{k+1} = (d_k ; Recent(R_{k−m:k}))`，**解決 batching 後 entity tracking 怎麼辦這個看似簡單但關鍵的問題**。和 PLACEMEM 的 capsule / ChronoMem 的 event log / CWL 的 typed DAG 是同族 primitive——**跨 batch boundary 的 continuity 是所有 batching-based memory 必須解決的 core 問題**。

4. **Typed schema + plan-guided retrieval = "schema-on-write, query-on-read"**：寫入時就 enforce 結構（typed schema、entities、topics、normalized temporal scopes、provenance），查詢時 route planner 只需 dispatch 不需 inference。**Collection 共識正在形成**：schema-on-write > schema-on-read（與 ChronoMem 的 event log、PLACEMEM 的 typed metadata contract、MemGraphRAG 的 structured graph 同向）。

5. **對 Sleeping Agent 的正面回應**：Sleeping Agent 證明 gist compression 系統性丟 temporal 表達（保留率 3.05%）。LycheeMemory V2 的 `T_i = normalized event/validity time` 把 temporal anchoring 從 implicit prompt 變 explicit schema field——**這是 schema-on-write 路線對 gist-style loss 的根本防禦**。Temporal reasoning +34.59 pp vs A-Mem 是這個 design choice 的直接驗證。
