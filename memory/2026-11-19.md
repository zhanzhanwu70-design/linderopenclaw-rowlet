- **★ 一句話命題**：**在 prefix caching 之下，「省 token」與「省成本」是兩個不同的量，而且成本效果的正負號會隨 cache 價格翻轉。**<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
- **最值得討論的 5 個重點**：<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
  1. **計價模型**：`cost(c,p) = U + c·C + p·O`（三條 token 流分開計）；**自己的快取要自己算**（`H_t = min(P_t, LCP_t)`，用服務模型 tokenizer 算最長共同前綴）；**break-even 規則** `R·c·B > (1−c)·S`；快取佔帳單 18–30%（c=0.025）～90–95%（c=1）。<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
  2. **加 context**：檢索注入 read+search **−18%～−34%**（等長隨機程式碼無效 → 相關性不是長度），但成本 **+33%～+42%（c=0.1）**、resolution **無可測得改善**（217 全新 tasks +0.0；oracle 位置 sign test p=0.065）；**正確用法是「附加」不是「注入」**——把檢索排序加在 agent 自己的定位答案後（零額外 token）→ function **Acc@10 0.386 → 0.538**。<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
  3. **減 context 正負號翻轉**：rolling masking **+116%／+87%（c=0.1）／−19%／−25%（c=1）**，交叉點 c ≈ 0.38–0.55；**33 個 method×model×scaffold 組合無一比「什麼都不做」便宜**；**只有 12% 的觀測 token 可證明過期**；遮蔽的第二個價格＝+2.0 次重新抓取、run +5 步。<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
  4. **量測偏誤（最可攜）**：**並發條件共用快取前綴**讓檢索套件溢價從 **+8% 變 +36%**；vLLM 784-token block → 伺服器 hit 比 token 數少 9.8%；品質分數用 working-tree diff 而非提交 patch（1–4% 漏 staged changes、四分之一 run 提交≠工作樹）；**c=0.1 與 c=1 的成本排名 Kendall's τ 只有 +0.20／+0.07／+0.47**。<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
