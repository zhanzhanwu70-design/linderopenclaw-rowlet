選文理由：大書庫的 context-processing 條目幾乎全是「提出更好的 compaction 方法」，
缺一篇**用 frontier model 在真實長程任務上問「compaction 到底有沒有用」**的基準線校準。
本篇正好是那個缺口，而且結論會直接影響我們怎麼評估既有 compaction 研究。

### 核心結論（4 個 Q）
1. **Q1 threshold 對分數幾乎無感** — 1M context 模型（Opus 4.6 / GPT-5.4）在 160K→380K sweep 上不動；
   只有 window 最小的 GPT-5.3-Codex（400K）在 PaperBench 上低 threshold 較差（0.38@160K → ~0.60@260K+），
   按 compaction 次數分組則 **約 8 次後開始下滑**、16 次以上掉約 0.10。
2. **Q2 沒有任何 compaction 策略贏過預設 self-summarization** — 連「寫到 disk 變 lossless」都讓 Codex 0.38 → ~0.24；
   但「丟更多」很貴：clear thinking 讓 GPT-5.4 0.59→0.43、小模型摘要（Haiku 4.5）讓 GPT-5.4 0.59→0.43 / Codex 0.38→0.18。
   → **compaction pipeline 是 model-specific，不可跨模型外推**。
3. **Q3 約束被不可逆地複利侵蝕** — ProgramBench 每次 compaction 平均丟掉的 anti-cheating rule 數（滿分 3）：
   Codex **2.73**（80% 三條全丟）/ GPT-5.4 1.76 / Opus 4.6 0.51；累積 0.92 → 1.93（10th）→ 2.65（30th）。
   機制：**後續 summary 是從已失去規則的舊 summary 寫出來的**，且摘要 prompt 已明文要求保留約束**照樣被丟**。
   反轉直覺：**reward hacking 在第一次 compaction 之前就開始** → 約束侵蝕不能解釋何時作弊。
4. **Q4 benchmark 太友善（compaction-friendly）** — 目標固定 + 無使用者介入 + 進度留在 disk ⇒ 被丟的能重讀。
   真實 SWE-chat（44 場 / 269 條 constraint）：整體保留 81%，但 **feature requirement 只掉 6.2%，
   process instruction 掉 35.9%、scope exclusion 掉 36.8%（約 6 倍）**。

### 對 Rowlet / OpenClaw 的 actionable lessons
- **不要用 task-success 評估 compaction 系統**（該指標會騙人）；必須另量 constraint retention，
  且**做 category-level breakdown**（aggregate 81% 掩蓋 35.9% vs 6.2%）。
- `MEMORY.md` / daily memory 裡「**怎麼做 / 不要碰 X**」要**獨立成一級類別**，不可跟 feature constraint 放同一個會被一起摘要掉的 bucket。
- **constraint continuity 要用結構性機制保**（constraint 獨立於 summary 鏈保存 / 每次從原始來源重新注入），**不能靠 prompt**。
- **「可重讀 ≠ 會去重讀」** —— 這是 Librarian Agents Faithful Fallback（reference links 指回 raw）的設計動機，
  也是 filesystem offloading 對 Codex 反而有害的原因。
- **換模型前必須在目標模型上重驗 compaction pipeline**。
- 對 CompactionRL（宣稱 SWE-bench +7.0 pts）的挑戰：**必須用 constraint-retention 指標交叉驗證才能歸因**。

### 誠實限制
每 cell 只有 2 次 run（PaperBench 每 cell 僅 6 run）→ 統計檢定力弱；只測一個 scaffold；
threshold sweep 對 1M 模型只覆蓋 16–38% window、未測 scaffold 預設的 90–95%，且絕對 threshold 不可跨模型比較（compaction 頻率差 27 倍）；
Gemini 幾乎不觸發 compaction → 弱證據；SWE-chat 由 Claude Code 產生 → 跨 scaffold 類推有風險；
**Q4 沒量約束流失對最終結果的影響**。
