### 四條最硬的

1. **核心命題：harness 把長輸出搬出 context 不是「讓 agent 看到少一點」，而是「讓 agent 可以選回答哪一份證據」**。
   損失**不在計算、不在容量**，而在 **agent 選了自我生成的輸出取代權威來源**（作者命名 **evidence substitution**）
2. **三段分解**：Build(p 產出) / Exposure(s 送達) / Closure(c 據此答對)，**Accuracy = p·s·c + unsupported**；
   對 5,773 條 trajectory **離線重跑 11,007 次 simulator call** 取得 ground truth，再對齊同一模型的 logged inline run 做 Shapley 分解。
   **GPT-5.1 −11.3 pp / GPT-5.2 −7.9 pp**；Claude Opus/Sonnet 與 **GPT-5.4 無可偵測差異**——**行為差異不跟廠商走**（GPT-5.4 像 Claude、其前代不像）
3. **淨值 ≈ 0 會掩蓋真實損失**：**GPT-5.4 的 build +4.1 pp 抵銷了 closure −7.2 pp**。→ context 管理決策**必須分階段報告**，不能只看 final accuracy（與 Compact-Bench 的 damaged/rescue 分開報同一原則）
4. **干預實驗**：**指名權威輸出**（TOC+Report）→ skipping 0.0%、closure 98.8%、**+6.3~+7.9 pp**，GPT-5.4 也被拉到 81.6% **且保住 retrieval 的 build 增益**；
   **Hybrid（塞得下就內聯、零指令）** 效果相同；**只教四捨五入完全無效**——**沒換 source、只換做法**。token 反而更省（58.0k→49.7k）

### 對我們的具體威脅（最重要的一條）

**Evidence substitution 正是我們 `MEMORY.md` 蒸餾層的風險**：agent 若讀自己寫的筆記 / 中間摘要而非原始 tool output 或 raw row，
蒸餾層會**自我強化成事實來源**。必須在 harness 指令層寫明「**權威來源是 raw row，不是蒸餾筆記**」——
這正是 TOC+Report 的做法，而 [[sources/eywa-provenance-grounded-long-term-memory|Eywa]] 的 Tier-0 + signal-anchored promotion 就是它的機制化版本。

### 可攜 protocol（下次可用）

- **配對重播**：checkpoint 取在「執行結果進模型之前」，兩臂共用檔案 / system prompt / 可見 history / 剩餘預算，**唯一差異是交付方式**；
  本文 **−9.4 pp [−14.5, −4.6]**，**115 份塞得進 inline 的 report 仍掉 −10.1 pp** → 損失不是放不下，是「選擇讀什麼」本身有成本。
  可攜到任何「要不要把這個輸出放進 context」的決策驗證。
- **Hybrid 是 safe default**：不需知道工具語意、不需額外指令、還更省 token → **檢索應是容量不足時的 fallback 而非預設路徑**。
- **導航成本本身是失敗模式**（Gemini：TOC 下 80/158 耗盡 24 步預算、median read_file 8 vs 2）→ 「讀取步數」與「放棄提交」該當一級指標監控。
- **評估 agent 優先選確定性工具**（模擬器/編譯器/測試套件）→ 失誤才能逐段歸因。
