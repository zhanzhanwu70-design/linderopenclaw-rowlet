
## 21:10 heartbeat — 覆核每日資安建議的「未結案」項（唯讀）

每日資安建議（21:05）留下三個「待 root 才能確認」。本輪逐項追查，**其中兩項已可確認（不需 root），一項仍需 root**：

### ① 高位 port owner — **已確認 8/9**
`rpcinfo -p 127.0.0.1` 直接對出：
- 57527 / 45825 / 53771 = **mountd**（rpc.mountd, pid 7148）
- 32961 = **status**（rpc.statd, pid 7144）
- 38307 = **nlockmgr**
- 43517 / 41799 / 40357 / 37429 = rpcbind 動態 port
→ **這 8 個「不明高位埠」全是 nfs-server/rpcbind 一套**，非獨立服務。停 `nfs-server` + `rpcbind` 可一次全清（`/etc/exports` 無實際匯出 → 零收益曝露）。

### ② 7070 — **仍是唯一未解，需 root**
- `/proc/net/tcp` 顯示 **uid=0**（root 持有）、inode 24913/24914、state 0A(LISTEN)
- 非 root 無法讀 root process 的 `/proc/<pid>/fd` → **逐一比對 inode 失敗（Permission denied / environ inaccessible）**
- 已排除：systemd unit 全部無 7070 設定、docker 無 container 映射、Tailscale 無 serve/funnel、cloudflared 另有自己的 20241（localhost only，`/ready` 回 `{"status":200,"readyConnections":4,...}`）
- curl `http://127.0.0.1:7070/` 與 `/metrics` 皆 **Empty reply from server**（非 HTTP 服務）
- 對照組：1716 = kdeconnectd（uid=1000）、5900 = x11vnc（uid=0）、2049/111 = nfs/rpcbind（uid=0）
→ **仍需 root 執行 `ss -tlnp | grep 7070` 或 `fuser -n tcp 7070` 才能確認 owner**。已寫入待辦。

### ③ sshd 有效設定 — **已確認（不需 root）**
`/etc/ssh/sshd_config` 中 `PasswordAuthentication` 與 `PermitRootLogin` **兩行都是註解**（第 62 行只有 `KbdInteractiveAuthentication no`）→ 有效值 = Ubuntu 22.04 預設（密碼驗證 yes、PermitRootLogin prohibit-password）。且 `~/.ssh/authorized_keys` 有 **5 條 ssh-ed25519**、`~/.ssh` 700 / `authorized_keys` 600 → **改 `PasswordAuthentication no` 是安全的，不會把自己鎖在門外**。
