4. **外部記憶後端** — 可插拔 Provider

**核心設計原則：**
- Memory.md 寫入後，**下次 Session 才生效**（刻意犧牲實时性以保住 System Prompt 緩存穩定）
- **Recall 不寫入 Transcript**（防止自我污染）
- **同一時間只允許一個外部 Provider 生效**
- Context Compression 前會先做 **Flush Memories**（知識轉移，不是簡單棄內容）
- **Background Review** 作為後台復盤（雙重機制容錯率高）

**對 OpenClaw 的啟發：**
- Session 級 System Prompt 緩存機制
- Recall 隔離設計
- Child Agent 不應有 Memory 寫入權限
- Compression 時的主動知識轉移

## LLM Wiki vs Carpathy LLM Wiki

**Carpathy LLM Wiki 特色**：LLM 充當編譯器，知識攝入時自動結構化編譯進 wiki 網絡
**OpenClaw llm-wiki**：Agent 充當編輯，知識手動寫入結構

**差異對比：**
- Carpathy：編譯 vs 檢索（知識進來時就建立連接）
- OpenClaw：圖書館員思維（需要 Agent 持續維護）

**可借鑒方向：**
- 寫入時讓 LLM 自動建立連接
- Obsidian 圖譜可視化
