
## 2026-11-13 02:40 — 「Rowlet 轉錄監控」automation 自動停用 10 次後修復並重新啟用

**觸發**：scheduled reminder（Automation `537bd0dd-32e6-4c4c-bbcc-c7026b618136`「Rowlet 轉錄監控」在連續 10 次執行失敗後被 auto-disabled）。

**根因（實測確認）**：
- automation 的 argv 是 `["sh","-lc","/home/amr/.openclaw/workspace-rowlet/scripts/transcription-monitor.sh"]`
- 錯誤摘要：`sh: 1: .../transcription-monitor.sh: Permission denied`，**exit code 126**
- 檔案權限是 **0600**（無執行位）→ `sh -lc` 直接執行該路徑時被拒
- **`ctime = 2026-11-12 21:07:48`** → 這是**前一天那次資安權限收緊批次**把這個腳本的執行位拿掉的（git HEAD 記錄的 mode 一直是 100755，工作樹被改成 644/600，狀態為 `M scripts/transcription-monitor.sh` 的 mode-only diff）
- **這就是「修一個安全問題、弄壞一個功能」的典型交叉**：資安批次把 `*.sh` 一起 chmod 成 600，順手打掉了 cron 依賴的執行位。

**修法**：`chmod 755 scripts/transcription-monitor.sh`（恢復 git 原本記錄的 100755），然後 `openclaw automations enable 537bd0dd-…`。
- **同時驗證**：`sh -n` 與 `bash -n` 語法檢查皆通過（腳本雖有 `#!/bin/bash` 與 `local`，但實際內容 dash 相容，無 `[[ ]]` / `function` / array bashism）→ 不需要改 argv 成 `bash -lc`，維持既有 payload。
- `--audit` 模式實測可跑：目前 42 筆 metadata → `completed: 40 / transcript_partial: 1 / transcript_ready: 1`，並列出 22 筆 `summary=False` 的歷史項目（舊資料缺 summary，非本次造成）。

**驗收**：`openclaw automations get` → `enabled: True`、`consecutiveErrors: 0`、**`lastRunStatus: ok`**（2026-11-13 02:45:00，耗時 1,167 ms）、`lastError: None`、`autoDisabled` 已清除。

**教訓（值得寫進維運規則）**：
1. **權限批次不能只按副檔名過濾** —— `*.sh` 同時是「安全檔案（可能含憑證）」與「可執行檔（cron 依賴）」。正確做法是**先列出依賴該檔案的 automation／cron，再排除**，或改為對每個被改動的檔案驗證「是否被某個 automation 以路徑方式執行」。
2. **automation 的 argv 用路徑直接執行 → 必須有執行位**。若 argv 是 `sh <path>` 形式，執行位其實不需要；本案是 `sh -lc "<path>"` → 走 execve → 需要執行位。
3. **mode-only diff 不會出現在一般 diff 輸出裡**，要靠 `git diff --summary` / `git ls-files -s` 才看得到 → **資安批次之後應做一次 mode 稽核**。
