## 🎯 最值得討論的 5 個重點

### 1. Lossless Recovery 取代 Lossy Compression
現有方法（summarization、pruning）會破壞證據，需要精確引用時失敗。VISTA 的核心主張有**數學證明支撐**：
> **Proposition 1（資訊理論下界）**：任何 non-recovering lossy 方法在 N→∞ 時成功率趨於 0。

取而代之：用 `archive(handle)` 把完整 payload 存進 hidden trajectory，用 ~0.1K token handle 取代，必要時 `retrieve(handle)` 無損恢復。類 virtual memory 的設計。

### 2. Proprioception（本體感覺）作為設計原則
LLM 本身就具備隱式的上下文狀態感知能力，只是缺少乾淨的介面讓它表達。VISTA 不訓練、不修改模型，而是給它一個 **Dashboard**（顯示 visible/archived blocks、token budget、access history），讓它自己決策何時 archive/retrieve。

> 這和 OpenClaw Rowlet 的啟發：如果 Rowlet 能「看到」自己的記憶使用量，或許能更動態地管理 daily memory vs MEMORY.md 的邊界。

### 3. Ablation 顯示三元件缺一不可
- 移除 archive（不存）→ -13.4%
- 移除 dashboard（無 proprioception）→ -13.4%
- 移除 recovery（lossy compression）→ -5.4%

Dashboard 對避免 over-archive 特別關鍵——沒有 feedback，agent 會過度存檔但忘了取回。

### 4. Handles as Address Space
~0.1K token 的 handle 代表完整 payload（實際在 hidden trajectory），需要時 retrieve 回來——有作業系統 virtual memory 的影子。這和 MemGPT 的 paging 類似，但更乾淨（lossless）。

### 5. 對比 ECHO vs ACE vs VISTA
| 維度 | VISTA | ECHO | ACE |
|------|-------|------|-----|
| 控制者 | Agent self-mediated | RL-trained | LLM Orchestrator |
| 可逆性 | ✓ (recovery) | ✗ | ✓ |
| 理論保證 | ✓ (Fano's) | ✗ | ✗ |
