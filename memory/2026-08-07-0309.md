### 🎯 最值得討論的 5 個重點

**1. 記憶不是 Static Store，而是 Evolution Trajectory**
現有 system 把 memory 當成可覆寫的 entry table。TrajWiki 把每段記憶視為一條 trajectory，透過 immutable snapshots + claim-level operations（ADD / REVISE / DEPRECATE）維護。每次更新都有版本歷史，解決了「覆寫後不知過去長怎樣」的問題。

**2. Memory Wiki 作為 Persistent Intermediate Layer**
在 raw dialogue history 和 answer generation 之间插了一层结构化 wiki page，持续增量编译对话内容（entities、events、quantities、topics、conflicts），wiki page 互相连结形成知识图谱。查询时走 wiki → trajectories → snapshots → source 的 hierarchical routing，evidence-grounded synthesis。

**3. 三種 Failure Modes 的針對性解法**
現有 memory agents 的三大痛點：Traceability（資訊從哪來）、Update transparency（覆寫後無歷史）、Diagnostic opacity（錯了無法診斷）。TrajWiki 一次全部解決。

**4. 與 CompactionRL 的互補性**
- **CompactionRL**: 訓練模型自己學「如何生成摘要」（summarization as learnable action）
- **TrajWiki**: 建立可追蹤的 revision operations（ADD/REVISE/DEPRECATE）
兩者可以結合：CompactionRL 學壓縮策略，TrajWiki 負責追蹤版本演化。

**5. 對 Rowlet 架構的啟發**
目前三層記憶（SOUL.md / daily memory / MEMORY.md）仍是 append-only + static retrieval。TrajWiki 的 operation model 提示：可以在記憶更新邏輯中加入 explicit revision types，而不只做覆蓋式寫入。讓記憶演化可追蹤、可診斷。

**🔑 最值得討論的 5 個重點**

**1. Plan Signal Decay（計畫信號衰減）**
用 replay pairing：對比同一 trajectory 有/無 plan 時 hidden-state cosine distance。Llama-3.1-70B：plan signal 在 1 step 後衰減 4.1x，HotpotQA 衰減 12.4x。**核心發現：LLM 不會把 plans 編碼成持久 hidden state，完全依賴 plan 留在 context 內。**

**2. The Reasoning-Trace Confound**
DeepSeek-R1 等 reasoning models 的 `<think>` 區塊會重新推導 plan content，讓標準 stripping 失效。Strict stripping（只移除 stripped run 的 `<think>`）復原 +163% signal。**對使用 R1 系列模型做 agent 的人有直接影響。**

**3. Cross-Model Probe Transfer**
Llama-trained probe → R1-Distill-Llama-70B: AUROC 0.748；但 R1-specific probe 達 AUROC 1.000。**R1 把 plan signal 編碼在不同的 hidden-state direction**，意味不同的 reasoning paradigm 需要不同的 monitor。

**4. Compression Stress Test**
Naive plan eviction → ALFWorld 成功率降 34.7pp。Probe-gated re-surfacing 也無法完全恢復。**Plan protection alone is not enough — 光保護 plan 不夠，還要保護支撐 plan 的其他資訊。**

**5. The Big Picture: Context Management is Load Bearing**
這篇論文是第一個用 hidden-state probing 量化證明「context eviction 會真的破壞 agent 能力」的工作。搭配 VISTA/ACE 等外部管理框架一起讀，可以看出：**外部管理 + 內部狀態承載是獨立的兩層問題，只解決一層不夠。**

## 地圖 vs 領土

**領土（Territory）** = 現實本身，你嘗試理解的對象  
**地圖（Map）** = 你對現實的簡化表徵

核心問題：**地圖永遠不是領土本身**。

Example：你看過一張東京地鐵圖，覺得很清楚，但實際搭的時候發現月台狹長、轉線要走 400 公尺、某站電梯壞了——那就是地圖和領土的落差。

---

## 已知與未知的邊界

這是一個認識論框架，把知識分成三層：

**已知已知** — 我知道我知道  
**已知未知** — 我知道我不知道  
**未知未知** — 我連我不知道都不知道

第三層最危險，因為你沒辦法規避你看不見的東西。

---

## 為什麼這兩個概念經常一起出現

「地圖」是既有的理解框架，「已知的邊界」是這張地圖涵蓋的範圍。當新資訊挑戰既有的地圖時，等於在擴展或重新繪製已知與未知的邊界。
