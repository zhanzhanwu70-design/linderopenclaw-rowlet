## 5 個最值得討論的重點

1. **Global sensemaking 是 vector RAG 的結構性盲區**。
   不是更大的 top-k 能修，是 index 形狀就錯。GraphRAG 把「找 chunk」變成「找 community summary」——是同一個 RAG family 的兩種 query 模式，不是新家族。

2. **預計算 amortizes 全域查詢**。
   Indexing 281 分鐘（1M tokens, 16GB VM, gpt-4-turbo）→ query time 是 map-reduce over pre-summarized communities。C0 root-level 比 TS text-summarization 省 97%+ tokens。
   跟 VISTA、HyMem 一樣的 pattern：cold phase 買 headroom，hot phase 跑便宜。

3. **Claims 跟 entities 同列一級公民**。
   時間敏感的 global query（「2024 年發生了什麼」、「主題如何演變」）沒 claims 就答不出來。
   wiki source 應該跟進：raw ingest 不只萃 entities/relationships，還要萃 dated claims。

4. **LLM-as-judge + Claimify-style atomic claim 是 no-gold-answer 評估的正解**。
   四準則（comprehensiveness / diversity / empowerment / directness 控制）+ claim 數量 / agglomerative cluster 數量做 cross-validation，78% 對齊率。
   wiki「這個 summarization 好不好」的判斷應採這個 template。

5. **Indexing cost 跟 entity matching 是兩個 silent reality**。
   281 分鐘 / 16GB VM 是 budget 現實；exact-string entity matching 是 paper 自己承認的 silent failure mode。
   graphify 升級方向明確：embedding-based fuzzy entity matching + offline indexing pipeline。

## 給 graphify / wiki 的 actionable lessons

- **Lesson 1**：對 `wiki/sources/` 預計算 cluster rollups（200 tokens/cluster），query path 只撈 rollup → 拿到 9×–43× per-query token reduction。1 天 prototype。
- **Lesson 2**：raw ingest 把 claims 升級為 first-class node type。
- **Lesson 3**：graphify 評估流程採 LLM-as-judge 四準則 + Claimify claim decomposition 做 cross-validate。
- **Lesson 4**：entity matching 換成 embedding-based（MiniMax embedding 可用）。
