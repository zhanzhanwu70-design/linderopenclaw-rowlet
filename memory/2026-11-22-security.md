### ② ★ 抓到 `kev-daily.sh` 的 `--check` 模式從未被實作
**症狀**：`kev-daily.sh --check` 的輸出與主模式**完全相同**（都印「未來 7 天內到期」與歷史逾期筆數），**沒有**「只列新增且 7 天內到期」與「逾期未處理」兩個區塊。
**根因**：腳本第 4 行註解宣稱支援 `--check`，但**從未把參數傳給 python**（`python3 - "$CUR" "$PREV" "$TODAY"` → 沒有 MODE），且**根本沒有 `if mode == 'check'` 分支**。
**修法**：`MODE="${1:-full}"` 傳入 → python 端加 `mode` 分支 → **並用 `case "${1:-}"` 解析**（第一版用 `MODE="${1:-full}"` 會把 `--check` 本身當 mode 值，仍走主分支 → 實測發現後再修）。
**過程中自抓到兩個自身的錯誤**：① f-string 巢狀引號 `f'...{v['dueDate']}...'` → Python 3.11 前語法錯（`SyntaxError: unmatched '['`）→ 拆成 `odays` 變數；② 第一版 MODE 解析錯 → 見上。
**修後實測**（用假造的 `kev-2026-11-18.json` 舊快照，不動正式快照）：`[新增] 5 筆` 正確列出 Apache Roller / vCenter / NetWeaver / Expressway / Chromium；`=== 新增且 7 天內到期 5 筆 ===` 與 `=== 逾期未處理 1780 筆 ===`（列出最近 10 筆含 Synology DSM、Apache Axis、SonicWall SSLVPN、CVE-2024-10441 等逾期 1–9 天者）兩個專屬區塊正確出現。**主模式仍正常**。測試用假快照已刪除（`state/kev/` 只留 `kev-2026-11-22.json`）。
