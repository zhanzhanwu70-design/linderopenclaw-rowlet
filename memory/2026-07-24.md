## VISTA 核心思想（討論用）

### 論文在說什麼
長期 tool agents 的 context 會不斷增長直到塞滿 window。現有方法要不是 system-controlled paging（agent 看不見），要不是 lossy compression（會丟證據）。VISTA 說：**模型本身就有 context 管理能力，只是缺少一個讓它「感受到」自己狀態的介面**。

### 三個值得討論的重點

#### 1. Lossy Compression 在長 context 必敗——資訊理論下界
- **命題**：任何 non-recovering lossy 方法，在 context block 數 N→∞ 時，精確引用成功率趨於 0
- **證明**：Fano's Lemma（list form）
- **討論點**：壓縮派（MemGPT-style recursive summarization）vs. VISTA 派的 lossless archive+retrieve——前者是無奈之舉還是策略選擇？

#### 2. Dashboard 即 Proprioception——給模型「內視」自己的能力
- Agent 可以看到每個 block 的 token 使用量、recency、access count
- 實驗：移除 dashboard 後準確率從 50.7% 降到 37.3%（-13.4pp）
- **討論點**：這是 interface 設計的勝利，還是 dashboard 本身增加了 reasoning 所需的「思考空間」？

#### 3. Archive as Virtual Memory——Handle 是地址空間
- Archived block 用 ~0.1K token handle 代表，實際 payload 在 hidden trajectory
- 類似 OS virtual memory：handle = pointer，retrieve = page fault + restore
- **討論點**：這種架構的 bottleneck 在哪？Hidden trajectory 本身也會持續增長嗎？

### 我的疑問（可在討論時提出）
1. VISTA 是 training-free，但 dashboard 本身需要足夠的 prompt space 讓模型「看到」狀態並决策。當 context 超級長時，dashboard 本身也會膨脹嗎？
2. Handle 的語意是由模型自己推斷的——這在不同模型間有多穩定？
3. 對 Rowlet 的啟發：目前我用的三分法（daily/MEMORY/工作目錄）是否可以進化成類似的 block-based archive/recover 機制？
