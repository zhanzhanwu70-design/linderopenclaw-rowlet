### Why MOSS matters for the field
The agent-memory literature is dominated by vector-RAG descendants (MemGPT/Mem0/Zep/A-MEM/AgeMem) and synthesis-based background memory (OpenAI Dreaming V3). MOSS is in a third camp — **symbolic SQL retrieval over a relational DB** — and it's the first one with year-long production evidence on a real personal corpus (110k segments / 44M tokens / 163k documents). The paper also introduces the **métacalque principle** (overlays as executable control structures, not annotations) which is genuinely novel — operationalizing Genette's Palimpsests + Malczewski's map algebra for agent memory.

### Rowlet-relevant takeaways (3-5 most discussion-worthy)
1. **「Small sliding window + scribe agent + relational DB」** = exactly Rowlet's current `daily raw + heartbeat curator + MEMORY.md` architecture, but production-validated. Affirms the design direction.
2. **Tier-0 immutable plain-text files** as substrate — MOSS agrees with Eywa that the source corpus must be append-only and human-readable. Rowlet's `memory/YYYY-MM-DD.md` already satisfies this if we add the discipline "never edit past evidence row, only append corrections".
3. **Inductive ontology > imposed taxonomy** for single-user corpus — Rowlet's MEMORY.md curation could in principle be derived inductively (graphify-style) rather than hand-curated. The 569 concepts / 322k annotations pattern is the target.
4. **Affective indexing (valence × activation per Russell circumplex) is one of the most used retrieval dimensions in practice** — actionable 1-day implementation: add 🟢🟡🔴 per-entry tag to MEMORY.md for "when was I excited/worried/bored about X" queries.
5. **The métacalque principle** formalizes Rowlet's existing 3-layer memory (daily / curated / context) as a 3-overlay stack with explicit extent boundaries. The framework gives names to what we already do.

### Notable structural insight
MOSS is structurally similar to [[sources/2609-scroll-context-as-environment-programmatic-context-management|Scroll]] (programmatic query over external state) — both reject "serialize everything into the prompt" — but Scroll puts the kernel inside Python and MOSS puts it inside SQL. Two different operational substrates for the same architectural move: from compression-of-context to retrieval-from-substrate.

### Limitations noted by paper (important to remember)
- Single-corpus single-user case study, not controlled benchmark.
- Determinism is retrieval-only, formulation still agentic stochastic.
- Multimodal enrichment in development (PDFs via Docling transcription).
- Multi-tenant isolation + memory poisoning defense are future engineering.
