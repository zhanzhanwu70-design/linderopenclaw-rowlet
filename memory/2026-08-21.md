### 為什麼選這篇

現有 collection 100% 都是 agent-side / application-side 設計（MemGPT、VISTA、ACE、ChronoMem、HyMem、CWL、CompactionRL、A-MEM、AtomMem、HippoRAG、Self-RAG...），**完全沒有 serving-stack 視角**。PLACEMEM 是首個明確把 cross-layer boundary 當 first-class systems abstraction 的工作，正好填補這個缺口。

### 5 個最值得討論的重點

1. **Cross-layer boundary 是新瓶頸，不是 length**：semantic memory ↔ runtime memory 各自優化造成雙重失敗（重複昂貴 prefill + 修正後繼續重用 stale compute artifact）。
2. **Capsule = single identity 同時綁定 meaning + compute**：versioned record 統一 facts / summaries / provenance / KV cache segments / embeddings / layer-frontier checkpoints。Replay policy 用 utility function 把 reuse 決策從 worker 提到 control plane。
3. **Forgetting = correctness primitive**：依賴 graph cascading invalidation 從 fact 修正傳遞到所有 derived artifacts。Pilot 顯示 runtime-only reuse 17 stale hits，full PLACEMEM **0 stale hits** 且 latency 同（**correction-aware control adds faithfulness at no latency cost**）。
4. **vLLM-first prototype 是務實的 control-plane heavy**：OpenAI-compatible routing sidecar + typed metadata contract，不 fork vLLM engine，layer-frontier replay 明確標示為 forward-compatible contract（honest scoping）。
5. **對 Rowlet 的 4 條 actionable lessons**：(a) Stack 視角盲點 — channel/skill/context routing 之間是否有 semantic stale state 風險；(b) Cascading invalidation 應為 primitive — MEMORY.md v2 應考慮 layer-frontier 失效；(c) Context engineering 不只看 prompt 端也要看 inference 端；(d) Correction-follow probe 可作為 OpenClaw 廉價 staleness audit。
