### 本次做法（可沿用）
1. 先跑格式稽核（trailing whitespace / 多餘空行 / 標題前缺空行 / 缺 EOF 換行 / 表格欄位數 / CRLF），
   再依 findings 修，不要憑感覺改。
2. 導覽表沿用 cpc repo 既有的 `## 快速導引`（問題 | 讀哪一節）樣式；ut-veteran 沿用 `## Quick navigation`（Question | Read）。
   新增前先用腳本驗證每個被引用的章節標題**確實存在**。
3. 導覽表要插在「該 anchor 標題之前」，插在之後會讓 anchor 章節變成空章節（本次踩過，見下）。
4. 內容完整性用 `difflib.SequenceMatcher` 驗：只允許 insert（導覽表／空行）與 blank-line delete，
   任何非空行被刪或被取代即中止不 commit。

### 踩坑（重要）
第一次套用導覽表的腳本寫錯，把「anchor 標題 + 導覽表」組成 `new`，又再接上 `txt[k:]`，
導致**整份檔案尾端被複製一次**（architecture.md 出現重複段落）。
事後靠 line-count 對照 HEAD 與 heading 序列檢查抓到。
→ 修正做法：`txt[:i] + block + txt[i:]`，並在寫入前 assert `txt in new`。

### 刻意沒做的事
- **不把 CRLF 檔轉成 LF**：`ut-veteran/references/maintenance-log.md`、
  `ut_cpc-skill/references/cpc-codebase-note.md`、`references/project-psw-0300a72-01-02.md`
  仍是全 CRLF（其餘檔皆 LF）。轉換會讓該檔 100% 行被視為修改，
  diff 會看起來像大量刪改，違反「確認沒有意外刪除大量內容」的可審查性要求。
  每次 run 只會看到這 1 個 repo 的那 1 個檔案，不要重複手動修。
- **不在 `references/maintenance-log.md` 加本次條目**：該檔的規則屬於
  `ut-veteran-maintenance` skill 的 critique→plan→execute 調查循環紀錄；
