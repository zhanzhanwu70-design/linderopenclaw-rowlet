- 選題理由：它是 context processing 的**「第一群」軸**（改 search-and-read harness 回傳什麼），而既有 wiki 的 AC3／ARCBench／Handoff Audit／LongHarness／REMORY 全是**「第二群」**（history-level compaction 或狀態管理）；CORE **完全沒做 history 壓縮**卻拿到 SOTA → 補上我們 harness 的盲區。<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
- **核心命題**：「哪段文字排得高」與「多少文字進到 agent 裡」是兩個問題；後者由 harness 決定，才是 context budget 的真正戰場。機制＝dense Top-300 passage → ColBERT MaxSim 取 10（每 parent doc ≤1）→ **在同一個 similarity matrix 上切 segment 得 snippet（零額外 encoding）**；context expansion（帶先前 passage id、只 score 該 doc、回原文不用輔助摘要模型）＋ cross-search **snippet 級**去重（key=docid+hash、精簡引用**保留 docid**、**已 append 的 observation 永不改寫 → 前綴不變**）。<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
- **主結果**：9 組 model×benchmark 全部第一；margin 隨語料規模擴大（GPT-5.4 對 OpenResearcher **+3.49 → +8.62 → +12.28**；Tongyi-30B-A3B **+0.24 → +1.29 → +14.03**）。**但「context 更省」只在 553M 語料成立**——100K／6M 語料上 CORE 的 peak context 反而**高於** OpenResearcher（42,732／257,004 vs 35,323／229,042），因為搜尋次數更多。<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
- **Component analysis 拆開 credit（各佔一半）**：No tools 4.58 → coarse only 62.61 → **+fine-grained 70.84（+8.23）** → **full CORE 80.12（再 +9.28）**。附錄另兩個被標題掩蓋的數字：**檢索粒度本身是變數**（doc-level 63.13% < passage-level 65.66%）、**agent 選擇本身被比較**（同跑 CORE 80.12 vs 62.41）。<!-- project: github.com/zhanzhanwu70-design/linderopenclaw-rowlet -->
