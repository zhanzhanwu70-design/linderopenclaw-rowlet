
## 每日論文討論（cron 58fe15dc）— 07:00 執行

讀 arXiv:2610.22273 **Librarian Agents: Training LLMs to Curate Long-Context Workspaces that Anticipate Future Queries**（Anikait Singh, Teresa Zhang, Yoonho Lee, Roshen Sanjay Nair〔Stanford〕, Aviral Kumar〔CMU〕, Chelsea Finn〔Stanford〕，2026-10-15，18 頁）。

選文理由：既有庫已飽和 reactive retrieval / compaction 方法論；本篇提出**第三條典範**——**anticipatory directed curation**：在 query 來之前就把 corpus 整理成可導航 workspace，且**「怎麼整理」本身是被 RL reward 過的 learned decision**（對照：reactive RAG 規則給定結構、GraphRAG/RAPTOR 預設 schema 給定結構）。

核心：
- **MDP 形式化**：Action=`CreateFile`/`MergeFiles`/`Delete`/`Stop`（Delete 永不刪 raw）。Reward 以**下游答題準確率**為主 `U(F)=S(F)−λ_tok·C_tok−λ_read·C_read`，**導航成本 penalty 只在答對時才計**（答錯 utility=0），否則 builder 會學「少讀文件亂猜」來降成本。
- dense reward `r_t=U(F_t)−U(F_{t−1})−α·Cost` 在 **γ=1 下與 sparse 目標完全等價**（potential-based reward shaping）；實作用**每 8 turn probe 一次 answerability** 取 delta + terminal correctness。
- BrowseComp-Plus **0.75 (Qwen3.5-4B) / 0.77 (Gemini 3.1 Flash Lite)** vs Embedding 0.42、Reranker 0.44 → **+33pp**；**No-FT ablation 只有 0.28，低於所有 reactive baseline → RL 是核心**。
- 建構成本：GraphRAG 11,923 tok/0.36、AutoCompaction 501,637/0.04、Ours 178,926/0.77 → **precomputation 便宜不等於有用**。
- 攤銷：accuracy 0.242→**0.637**，但每題 raw token **反而變多**（9,346 vs 1,238；讀檔 26.9 vs 2.7）→ 必須看 accuracy-normalized：10 題/corpus 少 **33.8%** token（ratio 0.662, CI [0.504, 0.836]），**break-even = 31 queries/corpus**（CI 18–54）→ **有門檻的投資**。
- 零樣本 BRIGHT avg pass@1 **52.0**（+31pp），StackOverflow 85.5；RL 改變建構行為（53.4 files/45.4 clusters/8.0 merges vs base 4.8/4.2/0.6）。
- **結構 ablation（最乾淨的一條）**：Flattened → 準確率不變（55.86→57.70）但**導航 token +51%**（3,635→5,497）；Shuffled → **準確率 −4.1pp**（51.72）且 token 不變 → **階層的主要價值是導航效率、語意位置本身帶資訊**。

給 Rowlet 的重點（llm-wiki 本身就是 anticipatory workspace）：
1. 目前蒸餾流程是**約定式固定流程**（對應 No FT = 0.28）→ 缺「以未來查詢命中率為 reward」的 learning signal
2. `wiki/log.md` 有大量條目但**沒有查詢次數統計** → 無法判斷 break-even（可直接補的量測缺口）
3. **頁面粒度以「淺路徑可達」為準則，不是「拆得乾淨」**（過度細碎→導航 token 上升）
4. **檔名與 cross-links 佈局是答案品質的一部分**（位置帶資訊）
5. `source_path` 指回 raw 原文正是 Faithful Fallback 的 wiki 實作——**已做對的設計**，值得在維持 raw 不可變原則時說出理由
