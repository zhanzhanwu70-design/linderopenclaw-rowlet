### 今日三條最硬的
1. **CVE-2026-46300 "Fragnesia"** — kernel `skb_try_coalesce()` 搬移 paged frag 時遺失 `SKBFL_SHARED_FRAG` marker →
   XFRM ESP-in-TCP 解密時誤判可 in-place 寫 page-cache → **本機 LPE / 容器逃逸**。
   CVSS 7.8（AV:L/PR:L）。CISA 10-28 收錄，**due 10-31（兩天後）**。
   - PoC 需要 `espintcp` 模組 → Ubuntu 說明指出需要該 module；**本機 CONFIG_INET_ESPINTCP=y 且 espintcp 已編進核心**（`/lib/modules/6.8.0-111-generic/kernel/net/ipv4/esp4.ko`），比「只是模組可用」更糟（無法用 modprobe 卸載來緩解）。
   - 已知利用鏈：PHP2Shell 拿下 web shell → Fragnesia 提權 → root。10-25 觀察到 25 台機器被這樣 root（3 台在美國）。
   - DirtyFrag 同家族（CVE-2026-43284 / CVE-2026-31431）走 xfrm_user/esp4/esp6 模組 → **本機 `xfrm_user` 已載入**。
   - Ubuntu 官方緩解（與 Dirty Flag 相同）：`kernel.unprivileged_userns_clone=0` + `user.max_user_namespaces=0`。
     本機現況：`unprivileged_userns_clone=1`、`max_user_namespaces=126852` → **未緩解**。
     但 docker 在用（docker group、containerd 跑著）、lxd 在群組裡 → 直接關 userns 會影響容器，需評估。
   - **正解是核心更新**：磁碟上已裝 `6.8.0-138`（含該 USN 修復），但 `uname -r` 仍是 `6.8.0-111`。
2. **AnyDesk CVE-2026-109390** — AnyDesk **before 8.0.3** mode-5 handler 長度未驗證 → 32-bit 加法 wrap → 分配極小 buffer → heap overflow → **未認證 root RCE**（CVSS 9.8）。PoC（AnyPwn）2026-10-08 公開。
   **本機 AnyDesk 8.0.0 + `--service` 常駐 + 0.0.0.0:7070 + 固定對外 IP 61.231.154.8 → 這是本機最可利用的一條。**
   apt 有 8.1.0（`apt-cache madison anydesk` → 8.1.0 可用）。
3. **OpenClaw 版本落後 + Node 版本卡在漏洞版**
   - 線上 gateway = OpenClaw **2026.8.2**；latest = **2026.10.8**；extended-stable = 2026.9.35。
   - **2026.10.6 起強制 Node ≥24.22.1（24 line）或 ≥26.12.1**，因為要擋掉 eMudhra CA 中間證金鑰被入侵後的 TLS chain（10 月有 8 張 eMudhra intermediate + 3 張 emSign root 被撤）。
     Node.js 不做 revocation check → 舊版**照樣驗得過** → 本機對外 TLS 連線（model API、web_fetch）都被該風險蓋到。
   - 昨天已把 `v24.22.1` 裝好、兩個 unit 檔與 agent-cli shim 都改指向它，**但 process 沒重啟** → 實機仍是 v24.19.0（marker `undefined` = 未修）。
