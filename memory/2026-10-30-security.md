### 今日最硬的三條
1. **CVE-2026-98432 — Kernel IPv4 TCP handshake UAF（CVSS 9.8，未進 KEV）**
   - `tcp_v4_syn_recv_sock()` 把 `ireq->ireq_opt` 的 ownership 轉給 child socket 但沒 copy；
     另一顆 CPU 同時處理同一 request socket 的 **retransmitted SYN** 並從 `tcp_check_req()` 送 SYNACK
     → `tcp_v4_send_synack()` / `inet_csk_route_req()` 在 `rcu_read_lock()` 下讀 `ireq_opt`，
     `ip_build_and_send_pkt()` / `ip_options_build()` 各讀兩次 `opt->optlen` → use-after-free。
   - **未認證、純網路可觸發（crafted SYN）、CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H。**
   - 上游 10-15 已修（stable 6.12.115 / 6.18.60 / 6.6.161 / 7.3.1），但 **10-30 Ubuntu 與 RHEL 都還沒有修正版套件**。
     → 本機 22.04 HWE 候選最高只到 **6.8.0-138**（建於 2026-08-07），**不含此修復**；
     等同 **CVE-2026-46300 也不在 138 裡**（138 的 changelog 只有 packaging resync，grep 不到 CVE-2026-46300/98432/43284/31431）。
     → **開機到 138 不會修掉這兩個 kernel 洞**，昨天報告裡「6.8.0-138 含 USN 修復」的說法今天用 changelog 證偽。
   - 本機曝險面：SSH 22 / x11vnc 5900 / AnyDesk 7070 / NFS 2049 / rpcbind 111 全在 0.0.0.0，
     **整機無防火牆**（ufw/nft/iptables/firewalld 全部未安裝、/proc/net/nf_tables 不存在）→ SYN flood / UAF 完全無阻擋。
   - 唯一現實緩解 = **關掉不必要對外 TCP 服務 + 上防火牆**（今日腳本第 4、5 步）。
2. **eMudhra CA 事件延燒（10-30 新聞）**
   - 8 張 intermediate CA 私鑰可從憑證本身還原（單一位數 PRNG → 暴力猜）。
     Chrome / Firefox / Apple / Microsoft 已停止信任；**Apple 於 10-17 收到通知，但 macOS 13.2（10-26 釋出）仍未修，
     macOS 指令列工具（git）今天仍信任受影響 CA**（Apple 官方說法：會在下一次更新處理）。
   - 本機對應：`/etc/ssl/certs/java/cacerts` 仍含 **emsign_root_ca_g1/g3/c1 + emsign_ecc_root_c3 + sectigo_*_root_r46/e46**（6 筆）。
     OpenJDK 11.0.32.1 已安裝，Java 應用走這份 truststore。
   - **Node.js 不做 revocation check** → 舊 runtime 不會因 CA 被撤而失敗，換 Node 版本才是真解。
3. **OpenClaw 執行面（self-audit，非新聞）**
