- 為何重要（對本機直接對應）：
  1. **零日壽命 = 被攻擊時間**。修補→武器化的窗口從「數週」壓到「數小時」，等 patch 公告反而可能成為起始訊號（GTIG：`exploit_agent` 已可在無人參與下比較 patch 差異→生成 exploit→執行）

  4. **本機就是 agent 主機**。我們的 agent 供應鏈（skill / plugin / MCP / 外連）就是同類攻擊面：22% 被標記的 MCP server 含 prompt injection、12% 市集 skill 遭污染的數據仍成立 → 對策不是「讓模型認得攻擊」，而是**先縮限 agent 能做的事**

## 三、一日提升方案（2026-11-24 21:00 → 2026-11-25 21:00）

### P0 — 需要 root 密碼，一次 45 分鐘可解 6 項（本機最高曝險）
1. **Chrome 158**（CVE-2026-125350 今日到期，剩 0 天）：
   `sudo dpkg -i ~/.cache/security-updates/google-chrome-stable_158.0.8127.36-1_amd64.deb`（sha256 已於 11-22 對官方 index 驗證相符）
2. **關 AnyDesk**（最大曝險面）：`sudo systemctl disable --now anydesk` → 收 7070 對外 + unattended access profile + 帳號私鑰（依據：最後使用 2026-07-28，43 次遠端連入紀錄）
3. **x11vnc 密碼檔權限**（第 9 天）：`sudo chmod 600 /etc/x11vnc.pass` → `sudo systemctl disable --now x11vnc` → 收 5900（⚠️ 若 Linder 仍用該遠端桌面通道，先確認再停）
4. **關 rpcbind / nfs-server**：`sudo systemctl disable --now nfs-server rpcbind` → 一次收 111 / 2049 / 數個 rpcbind 動態 port（/etc/exports 無實際匯出 → 零收益曝露）
5. **實查並收斂 ufw + IDS**：`sudo ufw status verbose` → 若規則為空 → `sudo ufw default deny incoming` + 只開 22（192.168.0.0/16、100.64.0.0/10）+ `sudo ufw enable`；`sudo apt install -y fail2ban`
6. **SSH 硬化**：`sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config` + `sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config` + `sudo systemctl reload ssh`（已驗 authorized_keys 5 條，不會鎖死）
