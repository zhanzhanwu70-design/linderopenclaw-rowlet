## 5 個最值得討論的重點

1. **範式轉移：unidirectional entropy → learned bidirectional classification**。
   LLMLingua 用 LLaMa-7B 算 token perplexity；LLMLingua-2 用 XLM-RoBERTa-large 做 preserve/discard 二分類。前者受單向 context 限制，後者捕獲 cross-sentence dependency。不是「換小模型」，是換了**什麼是「重要」**的計算定義。

2. **蒸餾信號的 quality gate 是必要而非裝飾**。
   GPT-4 蒸餾出來 15% 樣本被丟掉（top 5% VR + top 10% AG），剩下的 85% 訓練出來的模型**壓倒性**打敗未過濾版本。VR 抓 hallucinated word，AG 抓 noisy label alignment——這是 distill-from-LLM pipeline 的通用 pattern：teacher 不是 oracle。

3. **Faithfulness-by-construction = subsequence-only output**。
   因為模型只選原 token 子集，壓縮結果保證是原文本的 subsequence，**結構上不可能 hallucinate entity**。這一點跟 Beyond Compaction (CWL)、StreamingLLM（保留 prefix）共享——對 agent tool-use 是 critical 屬性，LongLLMLingua 的 abstractive 路徑就沒這保證。

4. **Task-agnostic ≠ task-aware 的失敗，task-agnostic 是 RAG 的 enabling primitive**。
   LongLLMingua 強在「給定 query 壓最相關」，但每次 query 都要重壓；RAG 場景同個 chunk 給上千 query 就要重壓上千次。LLMLingua-2 一次性預壓，跨 query 複用——**這是 architecture-level enabler**，不是效能小改。對 code-agent 的 memory layer（含 log traces、tool outputs、conversation history）同樣適用。

5. **5 條 hard constraint 是蒸餾品質的瓶頸和關鍵**。
   「only remove / no reorder / no change / no abbrev / no new words」這 5 條把 GPT-4 從「摘要生成」逼成「詞級刪減」。Chunk-wise (≤512 tokens) 對抗 GPT-4 在長 context 過度激進壓縮的 pathology。**兩者組合才讓蒸餾信號純粹**，否則 VR/AG 過濾再多也救不回——蒸餾 prompt 設計 + chunk 切分是 distill pipeline 的前 50% 成本。

## 和大書庫 stack 的對位

- 和 LongLLMingua：**同 family**，task-agnostic vs task-aware
- 和 StreamingLLM：**互補軸**——KV-level vs content-level
- 和 Beyond Compaction (CWL)：共享 subsequence-only-faithful 屬性
- 和 ACON：**互補設計空間**——LLMLingua-2 是固定 encoder + distilled labels，ACON 是 LLM-as-optimizer 改 compressor prompt in NL space
- 和 CompactionRL：兩者都 "learn to compress"，但 LLMLingua-2 改 small encoder，CompactionRL 改 agent weights via PPO

## 給 Rowlet 的 actionable note

LLMLingua-2 的 distill 套路（teacher LLM with hard constraints + quality gates + chunking）可以反向應用在 **MEMORY.md 自動蒸餾**：用 LLM 把長 daily memory 蒸餾成結構化條目，hard constraints（no new facts / no reorder）保證 fidelity，quality gate（VR-like：新增 entity 比例；AG-like：蒸餾後關鍵詞命中率）過濾低品質天。屬於未來 heartbeat skill 的 v2 候選。

### Uncle Bob 六大觀點
1. Agent 跟人一樣會被髒程式碼影響（鬼打牆）
2. 放棄寫規則到 prompt（lost in the middle）→ 改用 deterministic tools
3. CRAP 分數 + 突變測試 — 二十年前太貴的舊工具，現在 agent 讓它便宜
4. 五關 pipeline：規格員/撰寫員/清理員/強化員/QA → 1hr vs 人半天，4-5x 生產力
5. 門檻可調（CRAP 4→6→8）、紀律不可搬（不放棄 TDD 價值觀但用 Ousterhout 方式）
6. 規格驅動開發是瀑布鬼魂——動用文件當起點不當終點

### Rowlet 可應用的 takeaway
- 不要把紀律寫進提示詞——lost in the middle 會吃掉中間規則
- 把紀律變成 pipeline 關卡（deterministic tooling）
- 任務愈窄、context 愈短、U 型曲線損失愈小
- agent 用完即死、乾淨脈絡是奢侈品
- 規格是起點不是終點，計畫寫完即丟
- Rowlet 自己可以視為 OpenClaw 協調下的 sub-agent
