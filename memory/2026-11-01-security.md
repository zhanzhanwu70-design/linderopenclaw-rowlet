## 二、本機實測（今天校正了昨天的兩個錯判）

### ★ 校正 1：ufw **不是 MISSING，是「有裝、有 enabled、但設定被關掉」**
- `dpkg -l ufw` → `ii ufw 0.36.1-4ubuntu0.1`（**昨天寫「MISSING」是錯的**）。
- `systemctl is-enabled ufw` → **enabled**；`is-active ufw` → **active (exited)**，自 2026-10-11 18:13 起。
- **但 `/etc/ufw/ufw.conf` 是 `ENABLED=no`** → ufw 服務有跑，**卻沒有載入任何規則**，所以等於沒有防火牆。
- 佐證：`/var/log/ufw.log` 不存在（從沒真正啟用過）；`/etc/ufw/user.rules` 只有 307 bytes、日期 2024-09-11（空規則檔，amr 無讀權）。
- `/etc/default/ufw` 的 `DEFAULT_INPUT_POLICY="DROP"` 已存在（**這代表直接 enable 會擋掉 SSH，除非先 allow 22**）。
- `nft`、`iptables` 也在（`/usr/sbin/nft` 存在、ip_tables 模組載入中），先前「iptables MISSING」同樣是路徑/權限造成的誤判。
- **真正的修法不是「安裝 ufw」，而是 `sudo ufw allow 22/tcp` → `sudo ufw --force enable`（順序不能反，反了就鎖死 SSH）。**

### 一次跑完（建議在 Linder 面前複製貼上，**順序不可調換**）
```bash
# 0) 保留一條已建立的 SSH 連線（192.168.50.2 來的那條），不要關
# 1) AnyDesk：先升級再說（8.0.0 有在野利用的 CVE-2026-109390）
sudo apt-get update && sudo apt-get install --only-upgrade anydesk
# 2) 關掉沒在用的對外服務
sudo systemctl disable --now nfs-server rpcbind
sudo systemctl disable --now x11vnc      # 若要遠控，改走 Tailscale + 限 bind
sudo systemctl disable --now anydesk     # 若升級後仍不使用
# 3) 密碼檔權限
sudo chmod 600 /etc/x11vnc.pass
# 4) 防暴力破解
sudo apt-get install -y fail2ban
# 5) 防火牆：先放行 SSH 再 enable（順序反了會鎖死）
sudo ufw allow 22/tcp && sudo ufw --force enable
sudo ufw status verbose
# 6) sshd 收緊（先在另一終端驗過公鑰登入再 reload）
printf 'PasswordAuthentication no\nPermitRootLogin no\nMaxAuthTries 3\n' | sudo tee /etc/ssh/sshd_config.d/99-hardening.conf
sudo sshd -t && sudo systemctl reload ssh
# 7) 修開機核心（現在 GRUB 指向 2024-03 的 6.5.0-26！）
sudo sed -i 's|^GRUB_DEFAULT=.*|GRUB_DEFAULT="Advanced options for Ubuntu>Ubuntu, with Linux 6.8.0-138-generic"|' /etc/default/grub
sudo update-grub && reboot
```
> 備註：第 7 步的 6.8.0-138 **仍不含 CVE-2026-46300**（已用 changelog 驗證），這一步只是停止核心倒退到 2024 年，不是修 CVE。
