## Abstract

Large language models deployed as autonomous agents for enterprise workflows face a key challenge: verbose tool responses from enterprise systems can cause context overflow, stale-state errors, and high inference cost. We study this problem in automated expense itemization in Microsoft Dynamics 365 Finance and Operations using Model Context Protocol tools. We evaluate four GPT-5 configurations on a 50-task hotel expense benchmark: no user model, full conversation history, context pruned to the last 5 tool call/response pairs, and pruning with automated summarization. C4 (last-5 + summarization, window=3) achieves the best result: **91.6% complete itemization** and **99.64% average amount itemized**, with **553,374 tokens and 5.79 hours** — vs full-context 71.0% / 1,480,996 tokens / 14.56 hours. Results generalize across five expense types (three categories) and to Claude Sonnet 4.5.

## Core Method

**Recency-eviction policy operating on whole tool call/response pairs** (semantic unit), distinct from token-level prompt compression (LLMLingua / Selective Context) and external memory stores (MemoryBank / LongMem).

**Algorithm 1 — ConstructContext(H, N, W)**:
- N = keep window of recent tool call/response pairs (5 in main study)
- W = summary window (3 in main study)
- Evict `max(0, #tool − N)` oldest tool messages together with their preceding assistant tool-call message
- If W ≠ 0 and at least one pair evicted: summarize the W most recently evicted messages (single-pass LLM), insert at earliest evicted position
- Summary captures: forms opened, controls interacted with, buttons clicked, data entered
- **Cost: exactly one additional LLM call per eviction event**

**Configurations**:
- C1: GPT-5 only (no user model) — motivating ablation
- C2: GPT-5 + user model + full context — baseline
- C3: GPT-5 + user model + last 5 tool calls (N=5, W=0) — ablate summarization
- C4: GPT-5 + user model + last 5 + summarization (N=5, W=3) — main proposal

User model (gpt-4.1) held constant across C2–C4 to isolate context policy.

## Headline Results (50-task hotel benchmark, 5-run average)

| Config | Comp. Item. | <10% Rem. | ≥1 Item. | %Amt Item. | Total Tok (K) | Time (hrs) |
|--------|-------------|-----------|----------|------------|---------------|------------|
| C1 (no user) | 8.0% | 37.2% | 99.6% | 58.89% | 532.6 | 3.08 |
| C2 (full) | 71.0% | 74.0% | 100.0% | 92.03% | 1,481.0 | 14.56 |
| C3 (last 5) | 79.0% | 87.0% | 100.0% | 96.92% | 535.3 | 5.39 |
| **C4 (last 5 + sum)** | **91.6%** | **99.6%** | **100.0%** | **99.64%** | 553.4 | 5.79 |

**Statistical strength** (primary metric):
- C2: 71.0 ± 4.4, Wilson 95% CI [65.1, 76.3]
- C3: 79.0 ± 8.2, Wilson 95% CI [73.5, 83.6]
- C4: 91.6 ± 1.7, Wilson 95% CI [87.5, 94.4]
- C3→C4 Wilson intervals cleanly separated (strong pooled-trial evidence)

## Six-Mode Failure Taxonomy (50 tasks × 5 runs = 250 task-runs)

| Failure mode | C2 | C3 | C4 |
|---|---|---|---|
| Stale-state reference | 34 | 6 | 4 |
| Wrong subcategory mapping | 8 | 9 | 6 |
| Duplicate / skipped repeat item | 12 | 11 | 5 |
| Premature termination | 9 | 18 | 3 |
| Tool / form navigation error | 6 | 5 | 2 |
| Residual amount mismatch | 4 | 4 | 1 |
| **Total non-completions** | **73** | **53** | **21** |

**Key mechanistic finding**: C2→C3 cut stale-state errors 34→6 (older tool responses describe superseded form states, retaining them introduces noise). C3→C4 cut premature termination 18→3 (pure pruning loses task-level awareness; summary reinjects progress at +3.4% token overhead).

## Cross-Model Generalization (Claude Sonnet 4.5)

- Sonnet 4.5 does NOT stall without user model → C1 already reaches 88.0% complete itemization (vs GPT-5's 8.0%)
- Large GPT-5 C1→C2 gap reflects model-specific stalling behavior, not value of context engineering
- Context-engineering ordering preserved: Sonnet 4.5 C3 92.0% → C4 94.5% at +5.6% wall-clock premium

## Multi-Category Generalization

C2→C4 improvement remarkably stable across three structurally distinct categories:
- Hotel (n=50): 71.0 → 91.6 (+20.6 pts)
- Travel (n=30, car rental + flight): 76.0 → 95.0 (+19.0 pts)
- Meals & Gifts (n=32): 75.6 → 96.1 (+20.5 pts)

Token reduction 60–63%, runtime cut 57–60% across all categories.

## Sensitivity Analysis

Sweep over N and W shows results plateau beyond N=5 and show no accuracy gain for W>3 at non-trivial token cost, supporting the (N=5, W=3) operating point.
