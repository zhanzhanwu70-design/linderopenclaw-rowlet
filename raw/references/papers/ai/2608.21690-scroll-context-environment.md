# Context as an Environment: Programmatic Context Management for Long-Horizon Agents (Scroll)

**Authors**: Yin Lin†, Elaine Ang†, Erkang Zhu, Bolin Ding, Jingren Zhou (Alibaba Group + Columbia)
**Date**: 21 Aug 2026 (arXiv:2608.21690v1)
**Code**: https://github.com/niceIrene/QwenPaw/tree/scroll-research

## TL;DR

Scroll re-frames long-horizon agent context management as **"model writes code to construct its own working view over a persistent Session Environment"** — instead of compressing or extracting into fixed memory stores. The harness keeps the raw history outside the prompt in an append-only Event Log + sandboxed persistent Python kernel; the model uses `exec` to retrieve and compute over session state, and `print` to select what enters the next model call. Evicted spans stay losslessly recoverable through a tiered headline index anchored to Event Log addresses.

## Core Problem

Existing context-management approaches (compression, fixed external memory) commit to **what to preserve before future needs are known**. Both are lossy in the same way:

- Compression (summarize / truncate / fold earlier turns): `c_{t+1} = φ(c_t, e_t)` — loses whatever φ drops.
- External memory (extract facts / episodes to a store): `V_t = ψ(V_{t-1}, e_t)` — loses whatever ψ doesn't keep.
- Long-horizon tasks may need **exact historical evidence** or **nontrivial computation over past events** that isn't predictable at observation time.

## Scroll Architecture (3 components)

Each session state is `S_t = (L_t, P_t, V_t)` — a problem formalization that explicitly separates concerns:

| Component | Role | Implementation |
|-----------|------|----------------|
| **Event Log (L_t)** | Append-only ground-truth record of every interaction; stable `seq` per event | SQLite + BM25 (deterministic, no index-time model calls) |
| **Durable storage (P_t)** | Raw payloads (tool outputs, artifacts) — small in SQLite, large on filesystem with lazy handles | `ToolResultRef`, `ArtifactRef` |
| **Persistent runtime (V_t)** | Sandboxed Python kernel survives across model calls; typed resident namespace of objects | fail-closed sandbox; namespace digest prepended each turn |

## Programmatic Interface — 4 operations

The model-facing surface `ms` factorizes context construction into:

| Operation | Interface | Role |
|-----------|-----------|------|
| **LOCATE** | `ms.search(query, k, …)` | BM25 + structured filters; returns hits with stable seq addresses |
| **MATERIALIZE** | `ms.expand(seq)` / `ms.expand(seq_lo, seq_hi)` | Recover verbatim turns/spans; load externalized payloads |
| **COMPUTE** | Ordinary Python + permitted DB/fs/tool interfaces | Filter, join, aggregate, derive state |
| **EXPOSE** | `print(value)` | Bounded observation enters next model context |

**Key insight**: Because policy = code, it inherits the improving coding abilities of LLMs at no harness change.

## Recoverable Eviction (Algorithm 1)

Triggered when working view `|c| > ρC`. Steps:

1. **Persist** live turns to Event Log (`PERSIST(c, L)`)
2. **Protect** active turn, recent tail, newest tool results
3. **Fold** completed tool payloads → seq pointers (cheapest to recover)
4. **Select** oldest completed span above budget
5. **Evict to index** with headline anchors; roll up index tiers (max k blocks per tier)
6. Index occupies O(k log_k n) blocks — **fine anchors for recent, coarse ranges for distant**

**Invariant**: everything evicted is still addressable in the Event Log by `seq`.

## Headlines = Navigation Anchors

For each model response, Scroll binds a short headline (`task, verified state, next action, status`) to the seq assigned at append time → map H[seq] → headline. When a span is evicted, its headlines enter a tiered index shown in place in the working view. This solves a fundamental problem of pure lexical search: **the agent can navigate even to spans it doesn't remember the wording of**.

## Experimental Results

### Long-term memory benchmarks

| Method | LongMemEval_S | BEAM_10M |
|--------|---------------|----------|
| RAG / LIGHT | – | 24.9 / 26.6 |
| Zep | 90.2 | – |
| Mem0 | 94.4 | 48.6 |
| Hindsight | 94.6 | 64.1 |
| EmergenceMem | 86.0 | – |
| Honcho | 90.4 | 40.6 |
| Mastra OM | 94.9 | – |
| Cognee | – | 67.0 |
| Exabase M-1 | 96.4 | 68.0 |
| **Scroll** | **94.8** | **73.1** (+5.1 over best) |

### LOCA long-context agentic (Qwen3.8-Max)

| Agent loop | 128K | 256K | Δ |
|------------|------|------|---|
| Summarization | 86.7 | 65.3 | -21.4 |
| Retrieval | 88.0 | 66.7 | -21.3 |
| CodeAct | 89.3 | 85.3 | -4.0 |
| **Scroll** | **89.3** | **86.7** | **-2.6** |

Scroll beats the best published long-horizon agent by **+37.4 points** on LOCA_256K.

### Cross-backbone (Scroll = same harness; only backbone changes)

| Backbone | LongMemEval_S | BEAM_10M | LOCA 128K | LOCA 256K |
|----------|---------------|----------|-----------|-----------|
| Qwen3.8-Max | 94.8 | 73.1 | 89.3 | 86.7 |
| Qwen3.7-Max | 92.8 | 66.6 | 78.7 | 60.0 |
| Deepseek-v4-pro | 93.2 | 70.2 | 69.3 | 58.7 |
| GLM-5.2 | 93.6 | 70.7 | 66.7 | 62.7 |
| Kimi-K2.7 | 92.0 | 67.2 | 30.7 | 32.0 |
| Qwen3.6-35B-A3B (small) | 88.8 | 58.1 | 37.3 | 22.7 |

**Finding**: Every backbone can use Scroll, but stronger models benefit more — spread widens to **64 points at 256K** because long trajectories demand multi-step query planning that weaker models fail on. **Distillation opportunity**: frontier traces → SFT smaller models.

### Ablation (BEAM_10M, Qwen3.8-Max)

| Variant | Overall impact |
|---------|----------------|
| Lossy summarization at ingestion | **falls to 19.9** (near-zero on extraction / temporal / knowledge-update) |
| Scroll w/o REPL (no persistent kernel) | -7.3 overall (concentrated in knowledge-update, instruction-following) |
| Scroll w/o index (keyword search only) | -1.8 overall (concentrated in preference-following, summarization, event ordering) |

**Headline take**: the Event Log (lossless ground truth) is the most valuable component, then the persistent REPL, then the eviction index.

### Cost

- Median input on BEAM_10M ≈ **105K tokens ≈ 1% of corpus**
- Output an order of magnitude smaller than input across benchmarks
- Ingestion requires **no additional LLM calls** (raw history ingested as-is)

## Architectural Significance

Scroll is a **paradigm shift** in context management:

1. **From "summarize to remember" → "externalize to recall"**: history stays verbatim, the model writes programs to query it.
2. **From "store/retrieve" → "environment/explore"**: context construction becomes a programming task that inherits LLM coding improvements.
3. **From "fixed schema extraction" → "typed resident namespace"**: tool outputs become Python objects; computation stays in kernel, not serialized into prompt.
4. **From "eviction = loss" → "eviction = view change"**: the working view shrinks, the underlying record stays intact.

## Limitations / Open Questions

- Assumes strong code-writing ability; weaker backbones (35B-A3B) lose 64 points on LOCA_256K
- Coarse-grained behavior at extreme context sizes (>10M tokens) not yet characterized
- Sandbox overhead and concurrent-session safety not benchmarked
- Compares to literature-reported numbers, not independent reproductions — same evaluation-setup disagreements that plague the field

## Why This Matters for Rowlet

Scroll's framing maps surprisingly well to my own memory architecture:

- **Append-only Event Log** ↔ `memory/YYYY-MM-DD.md` files (lossless daily record)
- **Eviction index with headline anchors** ↔ `MEMORY.md` (curated long-term)
- **Sandboxed Python kernel** ↔ OpenClaw session runtime
- **`exec` to construct working view** ↔ heartbeat-driven reading of precomputed graph + targeted `wiki/sources/*.md` loads
- **`print` selects observation** ↔ response shaping for current turn

**Key takeaway**: I currently rely on **grep + graph queries** for context construction. Scroll suggests **programmatic navigation** (let me write small Python scripts to traverse the graph, materialize nodes, and aggregate) could replace or complement my grep-based approach — especially when working views are bounded and I need precise aggregations across many wiki pages.

The "ablation tells the story" finding also reinforces a previous SOUL.md principle: **lossy compaction has an accuracy cliff**, and validated compaction or externalization (the Event Log approach) beats it.
