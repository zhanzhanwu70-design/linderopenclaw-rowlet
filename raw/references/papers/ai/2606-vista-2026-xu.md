## 核心貢獻

### 問題
Long-horizon tool agents 被 context window 成長速度所瓶頸。現有系統將 context management 交给 agent 或 system 控制，但：
1. 學習式壓縮策略會丟棄證據（evidence）
2. 管理發生在 agent 看不到的 layer

→ **核心問題**：前沿 LLM 對自己的 context 是 "proprioceptively blind" 的——從 prompt 本身看不出 context 有多大、各 block 有多舊、用過多少次。

### 核心假設
**Capable models 本身就已經具備 context management 能力**，缺的不是學習到的壓縮策略，而是**一個介面（interface）暴露內部狀態**。

### VISTA（Visible Internal State for Tool Agents）
Training-free, model-agnostic 的 layer，核心功能：
1. **Typed, addressable blocks** — 將 working memory 表示為帶類型、可定址的 block
2. **Runtime dashboard** — 暴露每 block 的 token 使用量、recency、access history
3. **Archive as recoverable full-fidelity payloads** — 封存為可恢復的高保真 payload

### 實驗結果
- **LOCA-Bench**: Gemini-3-Flash 從 22.7% → 50.7%（+28pp！）
- 同一個 untrained interface 跨 1M / 100K / 10K 規模 trajectory 轉移
- Dashboard 本身（不只 archive/recovery）對效能有貢獻

## 關鍵洞察

1. **Context proprioception缺失** — LLM 無法從 prompt 推斷 context 使用狀態
2. **Training-free intervention** — 不需要 fine-tune，純粹是 interface 設計
3. **State dashboard > compression policy** — 讓 agent 自己看到、自己决策
4. **Cross-scale transfer** — 方法在不同 context 規模都有效
5. **Model-agnostic** — 四種 backbones 都有提升

## 與現有方法的比較

| 方法 | 控制者 | 缺點 |
|------|--------|------|
| MemGPT | System | 發生在 agent 看不到的 layer |
| Context Weaver | Learned policy | 會丟棄 evidence |
| VISTA | Agent 可見的 dashboard | Training-free, reversible |
