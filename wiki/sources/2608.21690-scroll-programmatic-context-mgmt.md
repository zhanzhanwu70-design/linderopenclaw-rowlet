# Context as an Environment: Programmatic Context Management for Long-Horizon Agents (Scroll)

> **One-line**: Context management as "model writes code to construct its own working view over a persistent Session Environment" — replaces compression/extraction with externalization + lossless recall.

## Problem with current approaches

Both compression and external-memory systems commit to **what to preserve before future needs are known**:

- **Compression** (summarize/truncate/fold): `c_{t+1} = φ(c_t, e_t)` — loses whatever φ drops.
- **External memory** (fact/episode extraction): `V_t = ψ(V_{t-1}, e_t)` — loses whatever ψ doesn't keep.

Long-horizon tasks need exact historical evidence or non-trivial computation over past events that isn't predictable at observation time.

## Scroll's three-component Session Environment

`S_t = (L_t, P_t, V_t)` — explicit decomposition:

- **Event Log (L_t)** — append-only ground truth, stable `seq` per event, SQLite + BM25 (deterministic, no index-time model calls)
- **Durable storage (P_t)** — payloads externalized to filesystem with lazy `ToolResultRef`/`ArtifactRef` handles
- **Persistent runtime (V_t)** — sandboxed Python kernel with typed resident namespace; survives across model calls

## Model-facing surface: `ms` (4 operations)

- `LOCATE`: `ms.search(query, k, ...)` → BM25 hits with seq addresses
- `MATERIALIZE`: `ms.expand(seq)` → verbatim recovery
- `COMPUTE`: ordinary Python + permitted DB/fs/tools
- `EXPOSE`: `print(value)` → only this enters next model context

**Policy = code** → inherits LLM coding improvements at no harness change.

## Recoverable eviction (Algorithm 1)

When `|c| > ρC`:
1. Persist live turns to Event Log
2. Protect active turn + recent tail + newest tool results
3. Fold completed tool payloads → seq pointers
4. Select oldest completed span above budget
5. Evict to tiered **headline index** (anchor H[seq] → headline at append time)
6. Roll up: O(k log_k n) blocks — fine anchors for recent, coarse ranges for distant

**Invariant**: every evicted span stays addressable in Event Log.

## Results

### Long-term memory benchmarks (best of literature as of Aug 15, 2026)

| Method | LongMemEval_S | BEAM_10M |
|--------|---------------|----------|
| Mem0 | 94.4 | 48.6 |
| Hindsight | 94.6 | 64.1 |
| Exabase M-1 | 96.4 | 68.0 |
| **Scroll** | **94.8** | **73.1** (+5.1) |

### LOCA long-context agentic (Qwen3.8-Max)

| Agent loop | 128K | 256K | Δ |
|------------|------|------|---|
| Summarization | 86.7 | 65.3 | -21.4 |
| Retrieval | 88.0 | 66.7 | -21.3 |
| CodeAct | 89.3 | 85.3 | -4.0 |
| **Scroll** | **89.3** | **86.7** | **-2.6** |

**Beats best published long-horizon agent by +37.4 points on LOCA_256K.**

### Ablation (BEAM_10M)

- Lossy summarization at ingestion → **falls to 19.9** (Event Log = most valuable)
- Scroll w/o REPL → -7.3 (kernel = 2nd most valuable)
- Scroll w/o index → -1.8 (concentrated in scattered-evidence categories)

### Cost

- Median input on BEAM_10M ≈ 105K tokens ≈ **1% of corpus**
- Ingestion requires **no additional LLM calls**

## Cross-backbone spread

| Backbone | LongMemEval_S | BEAM_10M | LOCA 256K |
|----------|---------------|----------|-----------|
| Qwen3.8-Max | 94.8 | 73.1 | 86.7 |
| Qwen3.7-Max | 92.8 | 66.6 | 60.0 |
| Deepseek-v4-pro | 93.2 | 70.2 | 58.7 |
| Kimi-K2.7 | 92.0 | 67.2 | 32.0 |
| Qwen3.6-35B-A3B | 88.8 | 58.1 | 22.7 |

Stronger models benefit more on long-trajectory tasks (LOCA 256K: 64-point spread). Suggests SFT/distillation of frontier traces into smaller models as future work.

## Connections

- **Builds on**: CodeAct (Wang et al., 2024), programmatic tool calling (Anthropic, 2025), lossless context (Zhang et al., 2025 / VISTA), MemGPT-style externalization (Packer et al., 2023), CoALA cognitive architecture (Sumers et al., 2024)
- **Position vs other recent memory systems**: Scroll doesn't extract → no extraction-stage loss. Mem0/Hindsight/Honcho all rely on fact/episode extraction; Scroll ingests raw history and lets the model write retrieval code per question.
- **Position vs Rowlet's three-tier memory**: See [[code-agent#scroll-programmatic-context-mgmt-2026-08-21]] for the architectural mapping.

## Key insights

1. **Lossless history > compressed memory** — ablation shows losing the Event Log costs 73 points.
2. **Code is the best retrieval policy representation** — it inherits LLM coding ability for free.
3. **Eviction ≠ loss** — eviction is a view change; original record stays addressable.
4. **Headlines > keyword search** — anchored navigation survives when wording is forgotten.
5. **Decompose `S_t = (L_t, P_t, V_t)`** — separates concerns that existing systems conflate.

## Open questions

- Behavior at >10M token corpora not characterized
- Sandbox overhead + concurrent-session safety unbenchmarked
- Compares to literature-reported numbers (same evaluation-setup caveats as rest of field)
- Cost-effective deployment at scale (kernel persistence vs stateless serving)
